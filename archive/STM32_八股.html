6.1 STM32 基础

151 单片机和 STM32 的架构有什么区别？★★
一句话51 是 8 位 CISC、资源少、分段寻址（64KB）；STM32 是 32 位 ARM Cortex-M RISC，线性寻址 4GB，带 NVIC 和丰富外设。核心差异是「位宽 + 指令集 + 中断/外设」三层。
展开：七维度对比表
维度51 单片机STM32
核心架构8 位，处理能力有限32 位 ARM Cortex-M，运算力强
指令集CISC，指令多效率较低RISC，指令少而高效，支持 Thumb
运算能力仅整数，无浮点硬件浮点（部分）+ DSP 指令
内存架构分段，最大寻址 64KB线性，可达 4GB 寻址
中断机制简单，2 级优先级NVIC 高级中断控制器，响应快
外设支持有限，基本控制丰富，适合复杂应用
功耗/性能功耗低、性能有限性能高，支持低功耗模式

选型逻辑：低实时、低成本 → 51；高实时、复杂功能 → STM32。

2Cortex-M3 和 Cortex-M4 在处理任务上有哪些主要区别？★★
一句话M4 = M3 + DSP 指令（SIMD/MAC） + 可选单精度 FPU，架构从 ARMv7-M 升级到 ARMv7E-M，更适合信号处理与复杂计算。
展开：架构/指令/浮点对比
特性Cortex-M3Cortex-M4
架构ARMv7-MARMv7E-M
DSP 支持不支持支持（MAC、SIMD 等 DSP 指令）
浮点单元 FPU不支持（软件库模拟）可选单精度 FPU，硬件加速
最大频率通常略低通常更高，适合实时运算
功耗较低略高，但计算效率显著提升
应用场景控制器、传感器管理音频处理、运动控制、信号分析
  • 指令集：M3 只支持基础 ARMv7-M；M4 额外支持 DSP 指令（SIMD 单指令多数据），加速向量/信号处理。
  • 浮点：M3 无硬件浮点，靠软件库效率低；M4 集成单精度 FPU，显著提升浮点性能。
3对比一下 STM32F1 和 STM32F4★
一句话F1 用 Cortex-M3（无 FPU/DSP，最高 72MHz）；F4 用 Cortex-M4（带 FPU/DSP，最高 180MHz），外设更丰富（USB OTG、以太网、高速 ADC）。
展开：对比表
维度STM32F1STM32F4
核心Cortex-M3，无 FPU/DSPCortex-M4，支持 FPU/DSP
主频24 ~ 72 MHz72 ~ 180 MHz
内存Flash 16KB~1MB，RAM 4KB~80KBFlash 64KB~2MB，RAM 20KB~192KB
外设基础外设，简单通信/控制丰富：USB OTG、以太网、高速 ADC
功耗低，适合低功耗场景略高，支持多种低功耗模式
场景预算有限的中低性能需求复杂、高性能实时控制

一句话记忆：F1「便宜够用」，F4「性能+外设升级版」。选型看性能/功耗/成本权衡。

4请你介绍一下 STM32 的启动流程？★★★
一句话上电复位 → 读向量表取 MSP 与复位向量 → 执行 Reset_Handler（搬 .data、清 .bss、设 MSP）→ SystemInit 配时钟 → 跳 main。启动模式由 BOOT0/BOOT1 决定。
展开：启动流程 & 启动模式
flowchart TD A[上电复位 POR / 外部 / 软件复位] --> B[读取向量表第 0 项: 初始 MSP] B --> C[读取向量表第 1 项: 复位向量 Reset_Handler] C --> D[Reset_Handler: 搬 .data 到 RAM / 清 .bss / 设 MSP] D --> E[SystemInit: 配置 PLL、系统时钟、外设时钟树] E --> F[跳转 main 函数] F --> G[外设初始化 + 主循环]
  • 系统复位：POR/外部/软件复位后，核心清状态，PC 跳到向量表起始地址，读 MSP（第 0 项）与复位向量（第 1 项）。
  • 向量表初始化：复位向量由启动模式决定，向量表位置可用 SCB->VTOR 重定位。
  • 启动代码：搬运 .data、清零 .bss、配置 MSP、调用 SystemInit 初始化时钟。

启动模式BOOT0BOOT1启动地址用途

软件消抖 · 延时法示例

// 延时法：按下后延时 10ms 再确认一次
if (HAL_GPIO_ReadPin(KEY_PORT, KEY_PIN) == GPIO_PIN_RESET) {
    HAL_Delay(10);                              // 跳过抖动期
    if (HAL_GPIO_ReadPin(KEY_PORT, KEY_PIN) == GPIO_PIN_RESET) {
        HAL_GPIO_TogglePin(LED_PORT, LED_PIN);  // 确认为有效按下
        while (HAL_GPIO_ReadPin(KEY_PORT, KEY_PIN) == GPIO_PIN_RESET); // 等释放
    }
}

软件消抖 · 计数法示例

// 计数法：连续多次读到相同电平才判定稳定
uint8_t key_debounce(uint8_t cur) {
    static uint8_t cnt = 0, last = 1;
    if (cur == last) {
        if (++cnt >= 20) { cnt = 0; return cur; } // 连续 20 次稳定
    } else {
        last = cur; cnt = 0;                        // 抖动, 重新计数
    }
    return 0xFF;                                    // 未稳定, 无事件
}
9嵌入式中栈的工作机制是什么？★★★
一句话栈是 LIFO 连续内存，SP 指向栈顶；函数调用分配栈帧、返回弹栈；ARM Cortex-M 栈从高地址向低地址增长；需防栈溢出（递归过深/局部变量过多/中断嵌套过多）。
展开：原理 / 过程 / 注意事项

基本机制

  • 栈由 SP（栈指针）指向栈顶，操作时 SP 上移/下移。
  • 用于保存函数调用上下文：返回地址、局部变量、参数；每次调用分配一个 栈帧，返回即释放。

工作过程

  • 函数调用：压栈返回地址/上下文（Push），为参数和局部变量分配栈帧。
  • 函数返回：弹栈（Pop）恢复 SP，返回地址弹到 PC 继续执行。
  • 中断：保存寄存器/PC 到栈，处理完恢复现场。

方向与分配

  • 多数 ARM Cortex-M 满递减：栈从高地址向低地址增长，堆反向增长。
  • 启动时 SP 初始化为栈区最高地址，运行中动态移动。

注意事项

  • 栈溢出：递归过深、局部变量过多、中断嵌套过多 → 覆盖其他内存致崩溃。
  • 合理分配：按任务复杂度、局部变量、嵌套深度配置栈大小。
  • RTOS：每个任务独立栈，需分别分配足够空间。

6.2 STM32 中断

10STM32 中断控制器是什么？★★★
一句话中断控制器是 NVIC（嵌套向量中断控制器），负责优先级、向量地址与中断嵌套；主优先级决定抢占、子优先级决定同级响应顺序。
展开：功能 / 硬件特性 / 应用

NVIC 主要功能

  • 向量表管理：按中断号找入口地址跳转。
  • 优先级配置：分主优先级（抢占）与子优先级（同级顺序）。
  • 使能/屏蔽：每个中断可单独使能或屏蔽。
  • 中断嵌套：高主优先级可抢占低优先级。
  • 系统异常：处理 HardFault、MemManage、BusFault、UsageFault。

硬件特性

  • 中断数量：低端 F0 最多 32 个，高端 H7 可达 240 个。
  • 优先级位数：常见 4 位或 8 位（4~256 级），由 AIRCR 寄存器位段配置。
  • 向量表位置：默认在 Flash 起始，可用 SCB->VTOR 重定位到 SRAM。

实际应用

  • RTOS 中用于任务调度与上下文切换。
  • 电机控制、通信协议等高实时响应。
  • 结合 Fault 异常做系统异常处理。
11STM32 中断处理过程是怎样的？★★★
一句话外设产生请求 → NVIC 判优 → 查向量表跳 ISR → 硬件压栈保存现场 → 执行 ISR 并清标志 → 出栈恢复跳回断点。
展开：流程图 & 关键寄存器
flowchart TD A[外设/系统事件产生中断请求] --> B[NVIC 判优: 使能状态 + 优先级] B -->|响应| C[查中断向量表, 取 ISR 入口地址] C --> D[硬件压栈: R0-R3 R12 LR PC xPSR] D --> E[执行 ISR: 读外设数据 / 清标志 / 触发外设] E --> F[出栈恢复现场, PC 跳回断点继续执行]
  • 中断触发：外设或系统事件（SysTick、软中断）向 NVIC 发出请求。
  • 向量跳转：NVIC 决定响应后查向量表，PC 跳到 ISR，硬件自动保存现场。
  • 执行 ISR：读数据、清标志（如 EXTI_PR）、触发外设；逻辑尽量短小。
  • 中断返回：从栈恢复寄存器/CPSR，PC 回断点。

12什么时候需要中断嵌套，什么时候不需要？★★
一句话高实时事件、优先级悬殊、RTOS 调度时需要嵌套；ISR 短小、单任务、共享资源易竞态的场合不需要（避免复杂度与竞态）。
展开：场景与控制方法

需要嵌套的场景

  • 实时性要求高：数据采集、紧急控制需快速响应高优先级事件。
  • 优先级差异明显：如定时器中断（时序）优先级高于 UART 接收。
  • RTOS 调度：任务切换依赖高优先级定时器中断触发。

不需要嵌套的场景

  • ISR 执行时间短：嵌套会增加复杂度和上下文切换开销。
  • 单一/低复杂系统：优先级相近，简单管理即可。
  • 避免竞态：多中断共享缓冲区无同步机制时，嵌套易致数据不一致。

如何控制嵌套

  • 配置主优先级（Preemption Priority）决定抢占关系。
  • 关键区用 disable_irq()/enable_irq() 临时屏蔽。
  • ISR 尽量简洁，复杂逻辑移出中断。
13Cortex-M 使用浮点运算对中断效率有什么影响？★
一句话ISR 用浮点需额外保存/恢复 FPU 寄存器（S0-S31、FPSCR），增加上下文切换开销；可用懒保存（Lazy Stacking）或把浮点移出中断优化。
展开：影响 & 优化
  • 上下文切换开销增加：保存/恢复 FPU 状态耗时，降低响应效率。
  • 嵌套影响更明显：多次嵌套叠加 FPU 状态保存开销。
  • 实时性受损：频繁浮点占用 CPU 时间，影响其他任务。

优化方法

  • 避免在中断中用浮点：复杂浮点计算移到主程序/低优先级任务。
  • 懒保存 Lazy Stacking：中断未实际用浮点则硬件不保存 FPU，减开销。
  • 精简 ISR：只做关键处理。
  • 合理优先级：减少嵌套次数，降低重复上下文切换。
14中断里往 buffer 放数据，buffer 由谁申请、谁释放？★★
一句话主程序/初始化阶段申请与释放（静态/全局 buffer），中断只负责写入并通知；中断内禁止 malloc/free。
展开：申请 / 释放 / 协作
  • 申请：系统初始化阶段由主程序完成，多用静态内存分配（全局/静态变量）；必须动态分配时也由主程序在任务运行前 malloc。中断内不动态申请（不可控延迟、内存碎片）。
  • 释放：数据处理完且不再使用时由主程序/任务负责释放；释放操作不放中断内。
  • 协作：中断写数据并用信号量/事件标志/中断标志通知；主程序读数据、处理并释放。

注意：中断与主程序对 buffer 的访问需互斥/信号量/环形缓冲保护；生命周期由固定模块管理。

15嵌入式系统中中断如何使用？需要注意哪些问题？★★★
一句话配置外设时钟/触发/优先级 → 写 ISR → 清标志；注意 ISR 短、少嵌套、配好优先级、清标志、不用复杂函数、保护共享资源、配栈大小。
展开：使用方法 & 注意事项

使用方法

  1. 配置：使能外设时钟，设触发模式（沿）和优先级。
  2. 向量表：中断请求跳到对应 ISR 入口。
  3. 写 ISR：读数据、清标志、触发任务。
  4. 清标志位：避免重复触发。
  5. 使能/屏蔽：经 NVIC 动态管理。

注意事项

  • ISR 简短：过长影响实时性，阻塞高优先级中断。
  • 避免嵌套过深：防栈消耗过大。
  • 合理优先级：定时器等时间关键任务设高优先级。
  • 清标志位：否则重复触发。
  • 不用复杂函数：中断内避免 malloc/free/printf（延迟/死锁）。
  • 保护共享资源：禁中断/互斥锁防数据竞争。
  • 配好栈空间：防上下文保存导致栈溢出。
16如果使用中断时非要延时该怎么办？★★
一句话中断里避免阻塞延时；改用硬件定时器 / 非阻塞计数（SysTick）/ 标志位+任务 / DMA 实现。
展开：替代方案
  • 硬件定时器：启动定时器，超时由另一中断处理，不阻塞当前中断。
  • 非阻塞延时：记录 SysTick 计数/全局变量，查询判断时间到达，不阻塞执行。
  • 标志位 + 任务（RTOS）：中断设标志/信号量，延时交给任务完成。
  • DMA 期间处理数据：靠 DMA 传输替代等待，减少中断占用。

注意：避免优先级反转/死锁；多嵌套场景关注嵌套深度与栈消耗。

17在中断中，保护现场需要保护哪些内容？★★★
一句话硬件自动压栈 R0-R3、R12、LR、PC、xPSR；软件手动保存 R4-R11（及浮点 S0-S31）；本质是保存「被打断程序的执行状态」以便正确恢复。
展开：寄存器 & 硬件/软件分工

需保护的内容

内容作用由谁保护
R0-R3参数与返回值硬件自动压栈
R12通用寄存器硬件自动压栈
LR返回地址硬件自动压栈
PC中断返回地址硬件自动压栈
xPSR状态/条件标志硬件自动压栈
R4-R11局部变量等通用寄存器软件手动 PUSH/POP
S0-S31/FPSCR浮点寄存器软件手动 / 懒保存
// 手动保存/恢复 R4-R11（硬件已自动保存 R0-R3、R12、LR、PC、xPSR）
__asm void SaveContext(void)    { PUSH {R4-R11} }
__asm void RestoreContext(void) { POP  {R4-R11} }
  • 硬件自动保护：Cortex-M 进入中断自动压 R0-R3、R12、LR、PC、xPSR（硬件栈帧）。
  • 软件手动保护：用到 R4-R11 或浮点寄存器时手动压栈（软件栈帧）。
  • RTOS：任务切换/中断上下文由内核负责保存恢复。

注意嵌套中断需覆盖更广；栈大小需合理配置防溢出。

18在中断中如何调用串口打印数据？★★
一句话中断里别用阻塞发送（HAL_UART_Transmit/printf）；改用非阻塞发送（IT/DMA）或只设标志位、由任务打印。
展开：三种做法 & 代码
  • 阻塞打印（不推荐）：中断内调用 HAL_UART_Transmit 长时间占用，影响实时性。
  • 非阻塞发送（推荐）：数据入缓冲，用 HAL_UART_Transmit_IT/DMA，外设中断/DMA 完成发送。
  • 标志位 + 任务（推荐）：中断只设标志/信号量，主任务完成打印。

推荐写法：中断只置标志位，任务打印

volatile uint8_t interrupt_flag = 0;

void EXTI0_IRQHandler(void) {
    if (HAL_GPIO_EXTI_GET_IT(GPIO_PIN_0) != RESET) {
        HAL_GPIO_EXTI_CLEAR_IT(GPIO_PIN_0);   // 清标志
        interrupt_flag = 1;                   // 只置标志, 不做耗时打印
    }
}

void MainTask(void) {
    while (1) {
        if (interrupt_flag) {
            interrupt_flag = 0;
            char msg[] = "Interrupt Triggered!\r\n";
            HAL_UART_Transmit(&huart1, (uint8_t*)msg, sizeof(msg)-1, HAL_MAX_DELAY);
        }
    }
}

19中断发生前数据如何保存，中断后去哪里取数据？★★★
一句话中断前硬件自动压栈保存上下文；中断后从堆栈恢复状态，从外设寄存器 / 共享缓冲区 / 消息队列获取事件数据。
展开：保存 & 获取来源

中断前：数据如何保存

  • 硬件自动保存：R0-R3、LR、PC、PSR 压栈。
  • 手动保存：R4-R12 / 浮点 S0-S31 由 ISR 开头保存。
  • 保护共享数据：禁中断/互斥锁保证全局变量一致。
  • 任务切换：RTOS 保存 SP 与 TCB，供任务恢复。

中断后：数据从哪里取

  • 堆栈恢复：出栈恢复寄存器/PC，硬件自动完成。
  • 外设寄存器：如 UART DR 取接收字节、定时器计数器取值。
  • 共享数据区：中断写入环形缓冲区，主程序轮询/标志/信号量读取。
  • 任务通信：消息队列、事件标志、信号量把数据交给任务。

6.3 DMA 传输

20什么是 DMA？★★★
一句话DMA（直接内存访问）：硬件绕开 CPU，在「外设↔内存、内存↔内存」间直接搬数据，CPU 只负责配置，减负提效、减少中断。
展开：原理 / 组件 / 模式 / 优点

核心组件

  • DMA 控制器：管理源地址、目标地址、大小、模式。
  • 通道 Channel：多通道并行管理多个外设传输。
  • 外设与内存：UART/SPI/ADC ↔ SRAM/Flash。

传输模式（方向）

  • 内存 → 外设（如内存发到 UART）。
  • 外设 → 内存（如 ADC 采集存入内存）。
  • 内存 → 内存（数据拷贝）。
  • 外设 → 外设（较少见）。

典型场景

  • UART 大批量收发、ADC/DAC 高速采集、SRAM→Flash 复制、实时系统非阻塞传输。

优点

  • 提高效率：CPU 不参与逐步传输。
  • 减少中断频率：批量传输优于逐字节中断。
  • 支持高速外设：匹配高速 ADC/UART/SPI 速率防丢数据。
21DMA 的配置流程是怎样的？★★★
一句话使能时钟 → 选通道配方向/源·目标地址/数据宽度/长度/优先级/模式 →（可选）使能中断 → 启动传输。
展开：流程图 & 配置代码
flowchart TD A[使能 DMA 及外设时钟 RCC] --> B[选通道, 配置方向与外设/内存地址] B --> C[配置数据宽度 / 长度 / 优先级 / 模式] C --> D{需要中断?} D -->|是| E[使能传输完成/半传/错误中断 + NVIC] D -->|否| F[启动传输 HAL_DMA_Start] E --> F F --> G[传输完成触发中断 / 回调处理]

配置要点

参数说明
源地址 Source传输起始地址（内存或外设）
目标地址 Destination传输目标地址
数据长度传输数据数量
方向 Direction内存↔外设、内存↔内存
数据宽度 Width字节 / 半字 / 字
优先级通道优先级
模式Normal（一次） / Circular（循环）

HAL 配置示例（内存 → UART）

// 1. 使能 DMA 与 UART 时钟
HAL_RCC_DMA1_CLK_ENABLE();
HAL_RCC_USART1_CLK_ENABLE();

// 2. 配置 DMA 通道
DMA_HandleTypeDef hdma_tx;
hdma_tx.Instance = DMA1_Channel4;                    // 通道
hdma_tx.Init.Direction = DMA_MEMORY_TO_PERIPH;       // 内存 -> 外设
hdma_tx.Init.PeriphInc = DMA_PINC_DISABLE;           // 外设地址不变
hdma_tx.Init.MemInc = DMA_MINC_ENABLE;               // 内存地址递增
hdma_tx.Init.PeriphDataAlignment = DMA_PDATAALIGN_BYTE;
hdma_tx.Init.MemDataAlignment = DMA_MDATAALIGN_BYTE;
hdma_tx.Init.Mode = DMA_NORMAL;                      // 单次模式
hdma_tx.Init.Priority = DMA_PRIORITY_LOW;
HAL_DMA_Init(&hdma_tx);

// 3. 绑定到 UART 并启动
__HAL_LINKDMA(&huart1, hdmatx, hdma_tx);
uint8_t data[] = "Hello DMA!";
HAL_UART_Transmit_DMA(&huart1, data, sizeof(data));

注意事项

  • 地址对齐：源/目标地址需字节/半字/字对齐。
  • 缓存一致性：带 Cache 的 CPU 需 Flush/Invalidate。
  • 中断优先级：合理设置，避免高频中断影响实时性。
  • 数据长度限制：受寄存器容量（16 位约 65535）限制。
22DMA 与缓存机制之间是如何协作的？★★★
一句话Cache 与主存不同步会导致数据不一致（DMA 读到旧数据 / CPU 读到过期数据）；用禁用缓存 / Flush / Invalidate / 非缓存区解决。
展开：两类不一致 & 解决

两种数据不一致

  • CPU 写 Cache 未回写：DMA 从主存读到旧数据。
  • DMA 写主存 Cache 未更新：CPU 从 Cache 读到过期数据。

解决方法

方法做法适用
禁用缓存DMA 相关区域标记非缓存简单，但降低性能
Cache Flush强制写回主存（DC CLEAN）CPU 写 → DMA 读
Cache Invalidate使缓存失效，从主存取新（DC INVALIDATE）DMA 写 → CPU 读
非缓存区域MMU/内存映射分配专用非缓存区彻底避免不一致
23在 DMA 传输数据时，如何保证 Buffer 的互斥？★★★
一句话DMA 与 CPU 并发访问 buffer 需互斥：双缓冲 / 状态标志位 / 互斥锁或信号量 / 缓存同步。
展开：互斥方法
方法原理适用
双缓冲 Double Buffering两 buffer 交替，一个 DMA 传、一个 CPU 用，传输完交换高实时，CPU 与 DMA 并行
状态标志位标志标识「使用中/可用」，操作前检查并更新简单、单 buffer
互斥锁 / 信号量任务取锁访问，DMA 完成发信号量通知RTOS 多任务
禁用缓存 / 手动同步操作前后 Flush/Invalidate 保证一致Cache 影响场景

选型：高实时 → 双缓冲；简单/单 buffer → 标志位；多任务 → 互斥锁/信号量。

24在有 Cache 的 CPU 上使用 DMA 时，如何保证数据一致性？★★
一句话CPU 写→DMA 读前 Flush；DMA 写→CPU 读前 Invalidate；或禁用缓存/用非缓存区。
展开：原因 & 实现步骤
  • 写缓存问题：CPU 写 Cache 未写回主存，DMA 读到旧数据。
  • 读缓存问题：DMA 写主存后 CPU 从 Cache 读过期数据。

具体步骤

  1. CPU 写 → DMA 读：CPU 写完执行 Cache Flush（写回主存），再启动 DMA。
  2. DMA 写 → CPU 读：DMA 完成后执行 Cache Invalidate（失效缓存），CPU 再读主存。
  3. 非缓存区：DMA 目标地址设为不可缓存区域，避免冲突。

Linux 下可用 dma_sync_single_for_device/for_cpu 等 API 管理同步。

25在串口通信中使用 DMA 时，如何选择传输模式？★★★
一句话一次性、固定长度 → 普通模式 Normal（完即停，需重启）；持续/实时流 → 循环模式 Circular（自动重启，需防覆盖）。
展开：两种模式对比
特性普通模式 Normal循环模式 Circular
适用场景一次性、固定长度（单次命令/短消息）持续接收（传感器、UART 数据流）
工作机制传完自动停止，需软件重启传完自动重启，无需软件干预
优点逻辑简单、易实现少 CPU 干预、实时性好
缺点每次需重新启动，不适合大批量数据覆盖写入，需标志/缓冲管理
  • 单次发送：发 "Hello World!" → 普通模式 + 完成后中断。
  • 实时接收：UART 数据流 → 循环模式 + 标志/中断判断数据量。

6.4 通信总线

26介绍一下常用的通信总线？★★★★★
一句话I²C（2 线、多主多从、低速）、SPI（4 线、全双工、高速）、UART（2 线、异步、点对点）、CAN（多主、抗干扰）、RS485（差分、半双工、远距）、USB（高速、热插拔）、以太网（TCP/IP）。按速率/距离/拓扑取舍。
展开：各总线 & 对比表
  • I²C：两线（SCL 时钟 + SDA 数据），同步串行，多主多从，7/10 位地址，100/400/3.4Mbps，适合传感器、EEPROM、RTC。
  • SPI：至少 4 线（SCLK/MOSI/MISO/CS），同步全双工，一主多从，几十 Mbps，适合显示屏、存储器、ADC/DAC。
  • UART：异步，无共享时钟，靠波特率同步，点对点，几米，9600~115200bps，适合调试、MCU↔PC。
  • CAN：多主、消息 ID 标识、仲裁无冲突，1Mbps、数百米，抗干扰强，适合汽车电子、工业控制。
  • RS485：差分（A/B 线）、半双工、多点（32~128 节点）、数千米、9600~1Mbps，适合工业现场。
  • USB：主从、热插拔即插即用，480Mbps(2.0)~5Gbps(3.0)，适合 PC 与外设。
  • 以太网：MAC 寻址、TCP/IP 协议栈、星型，10M~1Gbps、100 米，适合物联网/工控联网。

27485 是全双工还是半双工的？接收和发送冲突怎么办？★★★★★
一句话RS485 是半双工（差分 A/B 单总线，同时只能收或发）；冲突靠主从协议（Modbus）/ RE·DE 收发使能切换 / 冲突检测退避 / 延迟发送解决。
展开：半双工原因 & 冲突处理

为什么是半双工

  • 本质是单总线结构（A/B 差分对），所有设备共用。
  • 同时发送会信号冲突（总线竞争），接收端无法正确解析，故规定半双工。

冲突处理方法

  1. 主从模式协议：主设备管理时序，从设备仅在轮询/广播后应答（如 Modbus RTU）。
  2. 收发使能控制：RE/DE 引脚切换收发模式（DE 高发、RE 低收），发送后立即切回接收防回环。
  3. 冲突检测与恢复：发送时监听总线，检测到冲突停止发送、随机延时重试（类似 CSMA/CA）。
  4. 延迟发送：为每个从设备设唯一发送延迟，避免同时应答。
  5. 通信优先级：高优先级设备优先发送，低优先级等待。
28SPI 和 I²C 协议可以连接多个设备吗？最多多少？★★★★
一句话都支持多设备：SPI 靠独立 CS 引脚（受 GPIO 数量限制，一般 3~10 个）；I²C 靠从机地址（7 位约 112 个、受总线电容限制实际更少）。
展开：对比表
协议多设备方式数量限制扩展方法
SPI每个从设备独立 CS 片选引脚受主设备 GPIO 数量限制（3~10 个）译码器扩展 CS、菊花链
I²C共享 SDA/SCL，靠设备地址寻址7 位地址理论 128（可用 112）；10 位 1024；受总线电容（≤400pF）实际 10~20 个多路复用器分支、避免地址冲突
  • SPI：每个从设备需独立 CS；设备多了 GPIO 开销大，可用译码器扩展。
  • I²C：每设备唯一地址，主设备按地址寻址；10 位地址可更多。
29请介绍 UART 的特点、异步通信原理。★★★★
一句话UART 全双工、异步、无时钟线，靠约定波特率同步；帧 = 起始位(低) + 数据位(5~8) + 可选校验 + 停止位(高)，接收端在下降沿同步、位中点采样。
展开：特点 / 帧结构 / 异步原理

接口特点

  • 全双工 2 线（TX/RX），异步无时钟线。
  • 帧结构：起始位 + 数据位 + 校验位（可选）+ 停止位。
  • 优点：硬件成本低、简单；缺点：速率低，不适合大数据量。

异步通信原理

sequenceDiagram participant T as 发送端 participant R as 接收端 Note over T,R: 双方约定同一波特率(无共享时钟) T->>R: 空闲(高电平) T->>R: 起始位(拉低, 下降沿触发同步) T->>R: 数据位 D0..D7(LSB 先发) T->>R: 校验位(可选) T->>R: 停止位(高电平, 表示帧结束) Note over R: 位中点采样, 提高抗干扰
  • 数据同步：靠波特率（bps），双方预先约定。
  • 起始位同步：检测起始位下降沿识别帧开始。
  • 数据采样：在波特率周期中点采样，抗干扰；9600 时每比特约 104µs。
  • 传输结束：检测停止位确认帧结束。

波特率

  • 波特率 = 每秒传输符号数，常用 9600、19200、38400、115200。
  • 由 UART 分频器生成：波特率 = 输入时钟 / (分频系数 + 1)。
  • 误差需 < 2%，否则通信失败。
30SPI 和 UART 的区别？主从关系如何体现？如何主动读写？★★★★
一句话SPI 同步、4 线、高速、严格主从；UART 异步、2 线、低速、对等无主从。SPI 由主拉时钟主动发起，UART 双方可自由发收。
展开：对比 & 主从与主动读写
特性SPIUART

31SPI 的从设备是否可以主动读写主设备的数据？如何实现？★★★
一句话SPI 从设备天生被动（时钟由主驱动），不能主动发起；靠主轮询 / 从中断引脚通知 / 全双工双向交换 / 双主模式实现「伪主动」。
展开：四种实现方案
  1. 主设备定期轮询：主定时发命令帧询问，从设备按命令返回数据；简单，但增加主开销。
  2. 从设备中断通知：从设备数据就绪拉低 GPIO 通知主，主响应后发起通信读取；减少轮询负担，需额外引脚。
  3. 双向数据交换：全双工，主发命令同时从通过 MISO 返回预设数据；高效，但主动权仍在主。
  4. 双主模式：两设备按状态机切换主从，空闲时允许从变主主动发起；需仲裁防总线竞争，实现复杂。

核心结论：SPI 从设备本身无主动能力，所有「主动」都是借助主设备配合实现的。

32请比较 I²C、SPI、UART 的接收方式（轮询/中断/DMA）★★★★
一句话三者都有 轮询（简单费 CPU）/ 中断（省 CPU 易高频）/ DMA（高效适合大数据量） 三种接收方式，按速率与数据量选择。

接口轮询方式中断方式DMA 方式

SPI查 RXNE，简单易调试，适合小数据量提高实时性，适合中速（传感器采集）高效，适合高速/大数据（屏刷新、Flash 读）

  • 轮询：定期查状态寄存器，实现简单但 CPU 忙等，实时性低。
  • 中断：数据到达触发中断，CPU 在 ISR 读取，省 CPU 但高频中断易嵌套。
  • DMA：DMA 直传外设→内存，CPU 仅在完成后处理，高效但配置复杂、耗硬件。
33请介绍 I²C 的起始信号以及读写数据的步骤。★★★★
一句话起始信号 = SCL 高电平时 SDA 由高拉低；(写)起始+地址(w=0)+数据+ACK…+停止；(读)起始+地址(r=1)+数据+ACK/NACK+停止。停止 = SCL 高时 SDA 由低拉高。
展开：时序图 & 读写步骤
sequenceDiagram participant M as 主设备 participant S as 从设备 Note over M,S: 起始: SCL 高时 SDA 由高拉低 M->>S: ① 起始信号 Start M->>S: ② 7位从地址 + 方向位(写=0 / 读=1) S-->>M: ACK(地址匹配, 拉低 SDA) loop 每个字节 M->>S: 8位数据 S-->>M: 写:从回 ACK / 读:主回 ACK 或 NACK end M->>S: ③ 停止信号 Stop(SCL 高时 SDA 由低拉高)

起始 / 停止信号

  • 起始 Start：SCL 保持高电平，SDA 由高变低（下降沿）。
  • 停止 Stop：SCL 保持高电平，SDA 由低变高（上升沿）。
  • 应答 ACK：接收方在第 9 个时钟拉低 SDA 表示成功；NACK 保持高电平。

写数据步骤

  1. 主发起始信号。
  2. 发 7 位从地址 + 方向位（写 = 0），从设备地址匹配则回 ACK。
  3. 主逐字节发数据，从设备每收一个字节回 ACK。
  4. 发送完毕，主发停止信号结束。

读数据步骤

  1. 主发起始信号。
  2. 发 7 位从地址 + 方向位（读 = 1），从设备匹配则回 ACK。
  3. 主释放 SDA，从设备发数据；主收一字节回 ACK 请求下一字节，不再需要则回 NACK。
  4. 发停止信号结束通信。
