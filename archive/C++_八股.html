2能讲一下结构体的内存对齐问题吗？★★★
一句话成员按声明顺序存放，首成员地址=结构体地址；整体按最大成员对齐要求对齐，必要时插入填充字节，保证每个成员的起始地址满足对齐。
展开：规则 + 代码 + C++11 控制
  • 存储顺序：成员按声明顺序依次存放，结构体变量地址与第一个成员地址一致。
  • 默认对齐：结构体对齐 = 最大成员类型对齐要求的倍数（如有 double 就按 8 字节对齐）。
  • 内存填充：为满足对齐，成员间可能插入填充字节，避免性能下降或硬件异常。
struct S { char a; int b; short c; };   // 默认对齐：sizeof = 12
// a@0, 填充1字节, b@4, c@8~9, 整体补到 4 的倍数 → 12

C++11 对齐控制

  • alignof(T)：查询类型 T 的对齐要求（如 alignof(double) = 8）。
  • alignas(n)：指定变量/类型/结构体的对齐（如 alignas(16) struct S {...};）。
3C++ 从代码到可执行程序经历了哪些步骤？★★★★★
一句话四个阶段：预编译 → 编译 → 汇编 → 链接，最终生成可执行文件（链接又分静态链接与动态链接）。
展开：四阶段流程图 & 详解
flowchart LR A[源代码 .cpp] --> B[预编译
宏展开/头文件/条件编译] B --> C[编译
词法→语法→语义→优化
生成汇编 .s] C --> D[汇编
汇编→机器码
生成目标文件 .o] D --> E[链接

  1. 预编译：处理 `#` 指令——宏展开、条件编译（#if/#ifdef）、头文件包含（#include 递归展开）、删注释、保留 #pragma、加调试信息；生成 .i/.ii。
  2. 编译：词法分析（生成 token）→ 语法分析（生成语法树）→ 语义分析（类型检查等）→ 代码优化（常量折叠/死代码消除/循环优化）；生成汇编 .s。
  3. 汇编：汇编 → 机器码，生成目标文件 .o/.obj（可能还含未解析符号）。
  4. 链接：符号解析（函数/变量名匹配地址）+ 地址重定位（分配实际地址），合并目标文件与库成可执行程序。

5解释 int main(int argc, char *argv[]) 的参数？★
一句话argc=命令行参数个数（含程序名），argv=字符串指针数组，argv[0] 是程序名，argv[argc] 为 NULL。
展开：参数结构与内存
  • 运行 ./myprogram arg1 arg2 时 argc=3（程序名+2 个参数）。
  • argv 是指向指针数组的指针，argv[0]=程序名，argv[1]/argv[2]…为其余参数。
  • argv 数组以 argv[argc]（空指针 NULL）表示结束。
  • 内存：argc 为栈上整型；argv 在栈上，是指向字符数组（命令行参数字符串）的指针数组。
6main 函数的返回值有什么值得注意的地方？★★
一句话返回值类型必须为 int，是给 OS 的退出状态：0=成功，非 0=错误码（可自定义区分错误类型）。
展开
  • main 返回值传给调用者（操作系统），指示退出状态。
  • 返回 0：正常退出；非 0：异常/错误退出，可定义不同错误码。
  • 常用 getopt() 解析 -a/-b 等命令行选项。
7连续调用同一个函数两次，局部变量初始化结果一致吗？★★★
一句话取决于类型：基本类型未初始化则值未定义（可能不同）；类类型每次调构造（结果一致）；静态局部变量只初始化一次。
展开：函数调用过程 & 初始化结果

函数调用四步

  1. 压栈参数 → 跳转函数入口。
  2. 在栈上为局部变量分配空间。
  3. 执行函数体。
  4. 释放局部变量空间（栈帧弹出）→ 传递返回值。

初始化结果

局部变量类型结果
基本类型(int/float)未初始化值未定义，两次调用可能不同（取决于残留的栈内存）
类类型(std::string/自定义类)每次调用构造，结果一致
静态局部变量只初始化一次，后续保持上次值
8你知道 const 关键字吗？★★★
一句话const 定义只读常量，初始化后不可修改，可修饰变量/指针/函数参数/成员函数/返回值，提升安全性与可读性。
展开：四种常见用法 
// 1. 普通变量
const int x = 10;     // x = 20; 错误

// 2. 指针（详见 Q32）
const int* p  = &a;   // 指向内容不可改，指针可改
int* const p2 = &a;   // 指针本身不可改，内容可改

// 3. 函数参数（防止意外修改，传大对象常用 const 引用）
void f(const LargeObject& obj) { /* 只读 */ }

// 4. 成员函数（不修改对象状态，可被 const 对象调用）
int getData() const { return data; }
  • 修饰普通变量：值声明后不可改。
  • 修饰指针：可区分「指向的内容」与「指针本身」。
  • 修饰函数参数：函数体内不能改传入值。
  • 修饰成员函数：保证不改对象状态，可在 const 对象上调用。
9如何修改 const 常量？★★★
一句话可用 const_cast 去 const 或 memcpy 直接改内存绕过限制，但都属于未定义行为，不推荐。
展开：两种绕过方式 
const int x = 10;
int* p = const_cast<int*>(&x);
*p = 20;                     // 通过指针修改 const 变量（未定义行为）

const int x = 10; int y = 20;
memcpy((void*)&x, &y, sizeof(x)); // 直接操作内存修改 const（高风险）
  • const_cast：去除对象的 const 限制；若对象存于只读内存，修改会导致崩溃。
  • memcpy：绕过类型系统直接写内存，高风险。
  • 结论：这些操作可能引发未定义行为、降低可维护性，应尽量避免。
10const 属性在什么时候确定？★★★
一句话分两种：编译期常量（值编译时确定，可内联/常量折叠）与运行时常量（值运行时由函数/输入确定，编译器无法优化）。
展开：两类常量
类型确定时机编译器行为
编译期常量编译时确定（const int x = 10;）可内联、常量折叠，甚至不分配运行时内存
运行时常量运行时确定（const int x = getNum();）编译期不知其值，无法优化，运行时赋值后仍不可改

11指针和引用的区别？★★★★
一句话指针存地址、可为空、可改指向、可多级；引用是别名、必须初始化、不可改绑、更安全。
展开：完整对比表
特性指针引用
本质存储一个地址原变量的别名
级数可多级指针仅一级引用
是否可空可指向 nullptr不能为空，必须初始化
初始化后可变可改变指向不可改变目标
sizeof指针大小（地址大小）指对象（所绑变量）的大小
作函数参数传指针副本，改指向不影响实参传引用，改变直接影响实参
声明与初始化可先声明再初始化声明时即须初始化
12传函数参数时，何时用指针、何时用引用？★★★
一句话要改对象且可能传空/可不改时用指针；要改对象且保证有效时用引用；只读大对象传 const 引用 避免拷贝。
展开：选择依据
  • 需要修改对象：可空或可选 → 指针；不需判空、保证有效 → 引用（更简洁安全）。
  • 返回动态分配内存：只能用指针（引用无法表达「无对象」的悬空语义）。
  • 避免拷贝/栈开销：大对象、递归场景用引用；只读用 const 引用。
  • 可选参数：指针可传 nullptr 表达「缺省」。
13区别以下类型：int *p[10] 等★★★★
一句话int *p[10] 指针数组、int (*p)[10] 数组指针、int *p(int) 函数声明、int (*p)(int) 函数指针。
展开：四类声明辨析
声明含义
int *p[10]指针数组：10 个元素，每个是指向 int 的指针
int (*p)[10]数组指针：1 个指针，指向含 10 个 int 的数组
int *p(int)函数声明：p 是函数，接收 int、返回 int*
int (*p)(int)函数指针：指向「接收 int、返回 int」的函数
int func(int a) { return a * 2; }
int (*p)(int) = &func;   // 函数指针
int result = p(5);        // 等价 func(5)

int* p2(int a) { static int x=10; return &x; } // 返回 int* 的函数

16变量声明和定义的区别？★★★
一句话声明只告知类型与名字、不分配内存（可多次）；定义分配内存、创建变量（只能一次）。
展开 
extern int x;  // 声明：告知存在，不分配内存

  • 内存：声明不分配内存；定义分配内存并（可）初始化。
  • 次数：声明可多处（extern 跨文件）；定义只能一次，多处定义 → 链接错误。
  • 作用：声明用于跨文件共享，让链接器找到符号；定义在单一源文件。

77介绍一下常用 STL 的容器？★★★★★
一句话容器都是模板类，分三类：顺序容器（vector/deque/list）、关联容器（红黑树 set/map 等）、无序关联容器（哈希表 unordered 系列）、容器适配器（stack/queue/priority_queue）。
展开：分类与选型

（1）顺序容器

  • vector：连续动态数组，频繁随机访问+尾部操作；中间插入/删除会重分配、性能差。
  • deque：分段数组，两端高频操作；随机访问次于 vector。
  • list：双向链表，频繁中段插入/删除；不支持随机访问。

（2）关联容器（红黑树）

  • set / map：基于红黑树，键有序，插入/查找/删除均 O(logN)；map 每个节点为键值对。
  • multiset / multimap：允许键重复。

（3）无序关联容器（哈希表）

  • unordered_set / unordered_map：哈希表，均摊 O(1) 查找，最坏退化 O(N)。
  • unordered_multiset / unordered_multimap：允许键重复。

（4）容器适配器

  • stack：默认 deque 实现，后进先出。
  • queue：默认 deque 实现，先进先出。
  • priority_queue：基于堆实现，按优先级出队。
78deque 底层？块和块是如何连接起来的？★
一句话deque 底层是「分段数组」：多个定长内存块经一个中央指针数组（map）连接，两端各有指针支持高效头尾插删。
展开：块与 map
  • 块（block）：每块是定长数组，存若干元素（如 512/1024 个，实现决定）。
  • 指针数组（map）：核心管理结构，每个元素指向一个块；map 本身可动态扩缩。
  • 连接方式：map 记录各块地址，使所有块逻辑上连成连续序列。
  • 双端扩展：头尾各有指针指向首/末块；一端已满则分配新块并更新 map。

80介绍 vector 扩容原理★★★★★
一句话当 size()==capacity() 再插入时，vector 按约 2 倍分配新空间 → 拷贝/移动旧数据 → 释放旧内存 → 更新指针；缩容不会主动回收（除非 shrink_to_fit()）。
展开：扩容四步
flowchart TD A["size() == capacity() 且插入新元素"] --> B["倍增分配新空间
通常 2 倍 (或 1.5 倍)"] B --> C["拷贝/移动旧数据到新空间"] C --> D["释放旧内存空间"] D --> E["更新指针指向新内存"]
  • size() = 已存元素个数；capacity() = 已分配的总空间；容量-大小 = 剩余可用。
  • vector 内存分配在堆区，元素连续存储。
  • 扩容倍数与编译器实现相关（常见 2 倍或 1.5 倍），会造成内存分配+数据拷贝的性能开销。
  • 容量不会随元素减少自动缩小，需显式 shrink_to_fit() 或 swap 空 vector。

84C++ 左值引用和右值引用是啥？★★★

85STL 中 hashtable 的实现原理？★★
一句话STL hashtable 用开链法：若干个桶（bucket，由 vector 管理的指针数组），每桶一条自实现单向链表存冲突元素；桶数取一组固定质数，装填超限触发 rehashing。
展开：结构与扩容
  • 桶：本质是 vector 管理的指针数组，每指针指向一条链表头。
  • 节点：并非标准 list/slist，而是 hashtable 自定义的 hashtable_node。
  • 质数桶数：用 [53, 97, 193, …, 429496729] 一组质数做桶数量，哈希均匀分布。
  • rehashing：元素数超当前桶容量时，扩到下一更大质数容量并重新哈希全部元素。
  • 迭代器：只支持单向遍历（链表单向）。
  • 可自定义哈希函数；开链法带来链表额外内存开销。

2.5 智能指针

91介绍一下智能指针？★★★★★
一句话智能指针用 RAII 在出作用域时自动释放动态内存，防泄漏与非法访问；C++11 提供 unique_ptr（独占）、shared_ptr（共享/引用计数）、weak_ptr（弱引用，破循环引用），取代已废弃的 auto_ptr。
展开：三种指针
类型所有权特点适用
unique_ptr独占同一时间只有一个持有者；禁止拷贝，用 move 转移文件句柄、设备连接等明确独占资源
shared_ptr共享引用计数（use_count）跟踪，最后一个销毁时释放多对象/多线程共享同一资源
weak_ptr弱引用不增加引用计数，lock() 转 shared_ptr破循环引用、观察者
auto u1 = std::make_unique<int>(10);   // 独占
auto u2 = std::move(u1);                // 转移所有权，u1 空
auto s1 = std::make_shared<int>(10);
auto s2 = s1;                           // use_count = 2
std::weak_ptr<int> w = s1;
if (auto sp = w.lock()) { /* 资源仍存活 */ }
  • 引用计数增减自动完成；多线程同时访问同一 shared_ptr 仍需加锁。
  • 两个 shared_ptr 互相引用会循环引用，需 weak_ptr 破解。
92shared_ptr 是如何实现的？★★★
一句话核心是引用计数 + 控制块：shared_ptr 存「对象指针 + 指向控制块的指针」，拷贝/赋值将计数 +1，析构将计数 -1，计数归 0 时释放对象并清理控制块。
展开：引用计数机制
  • 控制块（Control Block）：存放 shared 引用计数、weak 引用计数、删除器 deleter、被管理对象指针。
  • 构造：接收裸指针，引用计数初始化为 1（空指针为 0）。
  • 拷贝构造/赋值：共享对象指针，引用计数 +1。
  • 析构：引用计数 -1，减到 0 则调 deleter 释放对象、清理控制块；大于 0 不释放。
std::shared_ptr<int> p1 = std::make_shared<int>(10);
std::shared_ptr<int> p2 = p1;       // 引用计数 +1
std::cout << p1.use_count();       // 输出 2
93手写智能指针？★★★
一句话手撕目标：实现「对象指针 + 堆上共享的引用计数」，拷贝时计数 +1、析构时 -1、归 0 释放；建议掌握到能脱手写出。
展开：最小 shared_ptr 骨架 
template<typename T>
class SharedPtr {
  T* ptr_;
  int* ref_count_;
public:
  explicit SharedPtr(T* p = nullptr)
      : ptr_(p), ref_count_(new int(1)) {}
  SharedPtr(const SharedPtr& other)
      : ptr_(other.ptr_), ref_count_(other.ref_count_) {
    ++(*ref_count_);
  }
  ~SharedPtr() {
    if (--(*ref_count_) == 0) { delete ptr_; delete ref_count_; }
  }
  T& operator*()  const { return *ptr_; }
  T* operator->() const { return ptr_; }
  int use_count() const { return *ref_count_; }
};
  • 要点：计数存堆上供多对象共享；拷贝浅拷贝指针、共享计数；析构仅归 0 才 delete。
  • 进阶：加移动语义、线程安全计数、weak 弱计数等。
94说说你了解的 auto_ptr 作用？★★
一句话auto_ptr 是 C++98 的失败尝试：靠析构自动释放内存解决泄漏，但用 delete 而非 delete[]、拷贝即转移所有权，缺陷太多，已被 unique_ptr/shared_ptr 取代（C++11 弃用）。
展开：特性与缺陷
  • 优点：构造函数接管、析构自动 delete，异常时也能释放（RAII 雏形）。
  • explicit 构造：裸指针不能隐式转 auto_ptr。
  • 独占：多对象不能管理同一指针，拷贝/赋值会转移所有权、原对象失效。
  • 缺陷：用 delete 而非 delete[]，不能管理数组（UB）；不兼容 STL 容器。
95智能指针出现循环引用怎么解决？★★★★★
一句话两个 shared_ptr 互指时引用计数永不为 0、内存泄漏；把其中一侧改成 weak_ptr（不增加计数）即可破环。
展开：成因与解法
flowchart TD A["shared_ptr<A> a (use_count=1)"] --"a->pb_ = b"--> B["A 持有 B (B 计数 2)"] B --"b->pa_ = a"--> C["B 持有 A (A 计数 2)"] C --> D["作用域结束，a/b 销毁
各剩 1，永远不为 0"] D --> E["A、B 均不析构 → 内存泄漏"] F["解法：B 侧用 weak_ptr<A> pa_"] --> G["不增加 A 的引用计数"] G --> H["a 销毁 → A 计数归 0 → 链式释放"] 
class B;
class A { public: std::shared_ptr<B> pb_; ~A(){ /*...*/ } };
class B { public: std::shared_ptr<A> pa_; ~B(){ /*...*/ } }; // 循环泄漏
// 改法：把 B 中 pa_ 换成 weak_ptr<A>，锁定时用 lock()
class B { public: std::weak_ptr<A> pa_; ~B(){ /*...*/ } };
  • 循环引用：A 和 B 互相持有 shared_ptr，各自 use_count 至少 1，作用域结束归不了 0。
  • weak_ptr 不参与生命周期管理，仅用于访问（lock() 判活再取）。

113为什么 C++ 中虚拟成员函数模板不被允许？★★★
一句话虚表要求所有虚函数编译期签名确定，而模板是调用时才按需实例化（类型组合无限）——静态虚表与动态实例化的根本冲突，故不允许。
展开：冲突点
  • 虚函数机制：靠虚表(vtable)做动态绑定，虚表在编译期构建，必须含全部签名。
  • 模板机制：调用时才实例化（Instantiation-on-Demand），类型组合潜在无限。
  • 冲突：编译器无法预知模板会实例化出哪些函数，无法在虚表预留槽位。

116C++ 中将临时变量作为返回值时的处理过程？★★
一句话临时变量（栈局部变量）出函数即销毁，但返回值安全：小值存寄存器、复杂对象靠 RVO 原地构造或移动语义转移，避免拷贝与悬垂。
展开：三种机制

  • RVO：复杂对象直接构造到调用者内存，免临时+拷贝。
  • 移动语义：返回右值时调移动构造，避免深拷贝。
  • 危险：返回局部变量的指针/引用是未定义行为（悬垂）。返回静态变量引用则安全。

117指针加减计算要注意什么？★★
一句话指针加减的单位是「所指向类型大小」：ptr+n 实际偏移 n × sizeof(T)；指针相减得元素个数（地址差 ÷ sizeof）。
展开：规则与示例 
int arr[] = {10,20,30,40,50};
int* p1 = &arr[1];   // 指向 20
int* p2 = &arr[4];   // 指向 50
*(p1 + 2);           // 40（向后 2 个 int）
*(p2 - 3);           // 20（向前 3 个 int）
(p2 - p1);           // 3（元素个数 = 字节差 / sizeof(int)）
  • 指针加法：ptr+n 向后移动 n 个数据类型大小。
  • 指针减法：ptr-n 向前移动。
  • 指针间减法：同数组内两指针差 = 元素个数。
118怎样判断两个浮点数是否相等？★★★
一句话浮点数是二进制近似，不能用 == 直接比；应设容差 epsilon，用 fabs(a-b) < epsilon 判断「近似相等」。
展开：容差法 
#include <cmath>
bool almostEqual(double a, double b, double eps = 1e-9) {
  return std::fabs(a - b) < eps;
}
double x = 0.1 + 0.2, y = 0.3;   // x ≈ 0.30000000000000004
almostEqual(x, y);                // true
  • 浮点存储为二进制近似，必然带来精度误差，== 易误判。
  • 机考/工程常用：取绝对值差小于一个极小容差即视为相等。
