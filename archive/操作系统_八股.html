3.1 概述

1计算机是怎么启动的？★★★
一句话通电后 BIOS 自检并找引导设备 → 读 MBR → 执行 Bootloader（GRUB）加载内核 → 内核初始化 → 启动用户态 init。
展开：四阶段启动流程
flowchart TD A[通电] --> B[BIOS 自检 + 初始化硬件] B --> C[读 MBR 主引导记录] C --> D[Bootloader GRUB] D --> E[加载内核 Kernel] E --> F[内核初始化 + 启动 init]
阶段主体职责
① BIOSBIOS电源自检（检测 CPU/内存/显卡），初始化硬件，按启动顺序找可引导设备
② MBR硬盘第 1 扇区(LBA0,512B)含分区表 + 引导程序，负责寻找活动分区并移交控制权
③ BootloaderGRUB / Windows Boot Manager加载操作系统内核（Kernel）
④ 内核Kernel + init内核载入内存、初始化资源与驱动，启动服务（Systemd），进入用户态
2操作系统的启动模式与保护模式？★★
一句话实模式=16 位、直接访问物理内存(≤1MB)、用于启动期；保护模式=用虚拟地址 + MMU 分页/分段管理内存，现代 OS 运行于此。
展开：两种模式 + 分段/分页
维度实模式保护模式
位宽16 位（早期 DOS）32/64 位（现代 OS）
寻址直接访问物理内存，≤ 1MB虚拟地址经 MMU 转物理地址
用途启动阶段、BIOS 初始化系统正常运行的核心模式

保护模式的两种内存管理

  • 分段：内存分若干段（段基址+段长），需预分配固定段，不适合大系统。
  • 分页：内存分固定大小页(4KB)，页表映射虚拟→物理，支持虚拟内存、进程隔离。
3Linux 中异常和中断的区别及特点？★★★★
一句话中断=外部硬件异步触发；异常=CPU 执行指令同步触发（除零/缺页）；系统调用=用户主动请求内核服务（也同步）。
展开：中断/异常/系统调用对比表
特性中断异常系统调用
来源外部硬件设备CPU 内部指令异常用户程序主动请求
触发方式异步同步同步
目的响应硬件事件处理运行错误提供系统服务
处理机制保存现场→ISR→恢复现场保存现场→异常处理→恢复/终止切内核态→执行服务→返回
典型场景键盘输入、硬盘读写完成除零、非法指令、缺页read()、文件读写、内存分配
4冯诺依曼结构是什么？对应现代计算机哪些部分？★★★★
一句话五大模块：运算器、控制器、存储器、输入设备、输出设备；指令和数据统一二进制存储、按地址访问。
展开：五模块对应现代硬件
冯诺依曼模块职责现代对应硬件
运算器算术/逻辑运算CPU 内 ALU
控制器取指、译码、协调数据流CPU 控制单元、南北桥芯片组
存储器存指令与数据内存 RAM、硬盘 HDD/SSD
输入设备向计算机传入数据键盘、鼠标、摄像头、扫描仪
输出设备呈现处理结果显示器、打印机、网卡
5一个由 C/C++ 编译的程序占用的内存分为哪几个部分？★★★★★
一句话五个区域：栈区、堆区、全局/静态区（data+BSS）、常量区、代码区(text)。
展开：五个内存区域
  • 栈区(stack)：向下增长，编译器自动管理，存函数参数/局部变量，函数结束自动释放。
  • 堆区(heap)：向上增长，程序员 new/malloc 分配、delete/free 释放，不释放会内存泄漏。
  • 全局/静态区：已初始化全局/静态变量 + 未初始化(BSS 段)，程序结束系统回收。
  • 常量区：存常量字符串等，只读，程序结束回收。
  • 代码区(text)：存机器指令，只读，防运行时被改。
6Linux / Windows 中栈空间的大小是多少？★★★★
一句话Linux 默认 8MB（ulimit -s 调），Windows 由编译器决定（VC++ 默认 1MB）。
展开：调整方式
平台默认大小调整方式
Linux8 MB (8192 KB)ulimit -s 32768（当前会话）；永久改 /etc/security/limits.conf
Windows由编译器定（VC++ 6.0 为 1 MB）编译器设置，改动固定

栈过小会 Stack Overflow，过大占用资源，需按需设置。

7Linux 中程序编译的过程（GCC 用法）？★★★★
一句话四阶段：预编译(-E) → 编译(-S) → 汇编(-c) → 链接，最终生成可执行文件。
展开：GCC 四阶段 
gcc -E hello.c -o hello.i   // 预编译：展开 #include/#define、删注释
gcc -S hello.i -o hello.s   // 编译：词法/语法/语义分析，生成汇编代码
gcc -c hello.s -o hello.o   // 汇编：生成机器码目标文件
gcc hello.o -o hello        // 链接：链接库文件，生成可执行文件
阶段命令生成文件作用
预编译gcc -E.i处理宏、头文件、注释
编译gcc -S.s源码转汇编
汇编gcc -c.o汇编转目标文件
链接gcc可执行文件链接库、符号解析

3.2 内存管理

8Windows 和 Linux 环境下内存分布情况？★★★★★
一句话分用户空间 + 内核空间；用户空间从低到高：代码段→data段→BSS段→堆(向上)→文件映射段(mmap)→栈(向下)。
展开：用户空间六个区域（低→高）
  1. 代码段(Text)：二进制指令，只读，低地址。
  2. 已初始化数据段(Data)：已赋初值的全局/静态变量。
  3. 未初始化数据段(BSS)：未初始化全局/静态变量，运行时清零。
  4. 堆段(Heap)：malloc/new 动态分配，低→高增长。
  5. 文件映射段：动态库(.so/.dll)、共享内存、mmap 映射。
  6. 栈段(Stack)：局部变量、函数参数、返回地址，高→低增长。

上方为内核空间，运行内核核心代码，用户程序不可直接访问。

9Linux 内存管理的实现是怎样的？★★★★★
一句话由分页 + 虚拟内存 + 交换 + 内存分配（伙伴系统/Slab）+ mmap 共同实现，多级页表 + MMU 完成地址映射。
展开：六大机制
  • 虚拟内存：每进程独立地址空间，按需加载，页表映射。
  • 分页：4KB 页 ↔ 页框，页表映射，缺页中断换入。
  • 交换(Swap)：内存不足时把不常用页写到交换分区/文件。
  • 伙伴系统：按 2 的幂次分块，合并相邻空闲块减碎片。
  • Slab 分配器：管理内核小对象，缓存复用减碎片。
  • 内存映射(mmap)：把文件/设备映射到地址空间，供访问与共享。
10常见内存分配方式有哪些？★★★★★
一句话三种：静态存储分配（编译期）、栈分配（函数作用域）、堆分配（运行时 malloc/new）。
展开：对比表
方式时机对象特点
静态存储分配编译期全局/静态变量整个运行期存在，效率高，可能浪费
栈内存分配函数调用局部变量、参数自动分配释放，效率极高，容量小(易溢出)
堆内存分配运行时malloc/new灵活，需显式 free/delete，易泄漏/碎片
11介绍一下动态分区分配算法？★★★★★
一句话四种：首次适应(低地址找第一个够用)、最佳适应(最小够用)、最坏适应(最大空闲)、邻近适应(从上次位置继续)。
展开：四算法对比 + 伪代码 
首次适应：从低地址起，找第一个满足的空闲分区分配
最佳适应：空闲分区按大小递增，选最小的满足分区
最坏适应：空闲分区按大小递减，选最大的分区
邻近适应：循环链表，从上次分配结束位置继续查找
算法优点缺点场景
首次适应简单、快低地址积累碎片性能高、管理简单
最佳适应碎片小、省大分区小碎片多、查找慢大任务、控碎片
最坏适应剩余区大、易后续分配浪费大分区、利用率低减小碎片、量大
邻近适应分配均匀、查找快末尾易生小碎片要求查找快、分配均匀
12虚拟技术你了解吗？★★★★★
一句话把物理实体变多个逻辑实体：时分复用→时间片轮转(多进程/线程)；空分复用→地址映射(虚拟内存)。
展开：时分 vs 空分
类型核心技术应用优点
时分复用时间片轮转多进程/多线程、CPU 调度提高处理器利用率、并发
空分复用地址映射虚拟内存、内存隔离独立地址空间、扩展内存
13虚拟内存介绍一下？★★★★★
一句话每进程独立虚拟地址空间；访问时才映射（延迟加载），MMU 用页表翻译，缺页时页面置换换入。
展开：工作原理
  • 虚拟地址空间分配：每进程独立（栈/堆/代码/数据段），隔离不冲突。
  • 延迟加载：初时虚拟地址只映射磁盘文件，访问才触发缺页加载。
  • 地址翻译：MMU 按页表把虚拟地址映射为物理地址。
  • 页表 + 页面置换：内存满时换出页面。

常见页面置换算法

  • FIFO：换出最早加载的页面。
  • LRU：换出最近最少使用的页面。
  • Clock：优化的 LRU，指针+引用位实现。
14虚拟内存的目的是什么？★★★★★
一句话核心是扩展物理内存（跑更大的程序）+ 内存抽象与隔离（进程间独立、简化编程）。
展开：三大目的
  • 扩展物理内存：逻辑地址空间可大于物理内存，按需加载运行超大程序。
  • 支持大程序运行：不必全量映射，有限物理内存也能运行更大程序。
  • 内存抽象与隔离：每进程独立地址空间，隔离增强安全，程序员无需关心物理分布。
15详细介绍一下内存管理与分页？★★★★
一句话分页把内存划固定大小：虚拟内存的「页」↔ 物理内存的「页框」，由页表映射，消除外部碎片、按需加载。
展开：页表项结构 + 分页 vs 分段

页表项字段

  • 页号：虚拟页编号。
  • 页框号：映射到的物理页框。
  • 有效位：页是否在内存。
  • 权限位：读/写/执行。
  • 访问时间：供置换算法用。

分页 vs 分段（易混）

维度分页分段
划分依据固定大小页(4KB)逻辑段（代码/数据/栈）
碎片无外部碎片，有内部碎片有外部碎片
对用户可见不可见可见
16虚拟地址怎么转换到物理地址？★★★★★
一句话虚拟地址 = 页号 + 页内偏移；页号经 TLB/页表 查物理页框号，页框号 + 偏移 = 物理地址；未命中则缺页换入。
展开：转换流程图
flowchart TD A[虚拟地址 = 页号 | 页内偏移] --> B{TLB 命中?} B -- 命中 --> C[直接取物理页框号] B -- 未命中 --> D[查页表] D --> E{页表项有效?} E -- 有效 --> C E -- 无效 --> F[缺页中断: 从磁盘换入页面] F --> D C --> G[物理地址 = 页框号 + 页内偏移] G --> H[访问物理内存]
  • TLB：高速缓存最近页表项，命中则跳过页表访问，加速转换。
  • 缺页：页表项无效→缺页中断→从磁盘加载页面→更新页表→重新执行指令。
  • 页置换：内存满时按 LRU/FIFO 选页面换出。
17页表实现机制是什么？★★★
一句话三种：单级页表(简单占内存大)、多级页表(省内存但多级访问慢)、反向页表(按物理页框记录,省内存但查复杂)。
展开：三种页表对比
类型结构优点缺点
单级页表线性数组，页号直接索引简单、查找快大系统占内存巨大
多级页表层次化，虚拟地址分多段索引只用到的地址分配页表，省内存多次访存，延迟高
反向页表物理页框→虚拟页映射省内存查找复杂，需遍历/散列
18分页有哪些缺点？★★★
一句话页表占用内存大、多级页表查找慢（TLB 未命中）、仍有内部碎片。
展开：三大缺点
  • 页表占用内存过大：大地址空间/多进程各维护页表，开销大。
  • 页表查找时间长：多级页表需多次访存，TLB 未命中时明显。
  • 内存碎片化：固定大小页导致内部碎片（一页用不满）。
19分页是否会导致内存碎片？★★★
一句话分页消除外部碎片（任意空闲页框可被任意页用），但仍有内部碎片（页内未用空间）。
展开：两种碎片
  • 外部碎片：因固定页框 + 页表映射，空闲页框都能被用，几乎消除。
  • 内部碎片：进程需求装不满一页时，页内剩余空间浪费（如 4KB 页存 6KB 需 2 页，剩 2KB 碎片）。
20进程间共享内存的分配是怎样的？★★★
一句话内核创建共享内存并映射到各进程用户空间；读写无需内核中转、零拷贝，是最快 IPC（但创建/权限/映射需内核参与）。
展开：三个要点
  • 分配位置：内核空间创建，再映射到各进程用户空间地址。
  • 速度最快：无数据复制、直接内存访问，仅次于本进程内存访问。
  • 是否经内核：数据交换在用户空间完成不经内核；但创建、权限、映射仍需内核。
21堆和栈分配对象的效率比较？★★★
一句话栈分配仅调栈指针 + 一次访存、快但容量小；堆需查空闲块 + 两次访存、慢但灵活大。
展开：堆 vs 栈对比表
维度栈(stack)堆(heap)
分配/释放调栈指针，自动，极快malloc/new 查空闲块，需 free/delete

22进程、线程和协程的区别与联系？★★★★
一句话进程=资源分配单位(独立地址空间)；线程=调度执行单位(共享进程资源)；协程=用户态轻量线程(自行调度)。
展开：三者对比表

23操作系统在什么情况下会启用调度器？★★★
一句话进程创建/终止/切换、中断处理返回、同步原语等待时，调度器介入选下一个进程。
展开：五种触发时机

  • 进程终止：CPU 空闲，选下一进程。
  • 进程切换：时间片用完/系统调用/等 I/O，暂停当前进选新进程。
  • 中断处理：硬/软中断后决定恢复原进程还是切换。
  • 同步原语：信号量/互斥量等待时挂起等待进程，调度其他进程。
24进程 A 改动了变量，进程 B 能读到新值吗？★★★★
一句话只有通过共享内存(shmget/shmat)或文件映射(mmap)映射同一物理内存时才可见；普通独立地址空间看不到。
展开
  • 独立地址空间：两进程虚拟地址映射不同，改普通变量互不影响。
  • 共享内存：映射同一物理内存，A 改 B 立即看到。用 shmget/shmat 或 mmap。
  • 内核态共享数据：内核通过共享内存机制实现跨进程共享。
25介绍一下你对操作系统的理解？★★★★

展开：六大职能
  • 资源管理：CPU/内存/存储/IO/网络分配与调度。
  • 进程管理：进程创建、调度、同步、通信、销毁。
  • 内存管理：分配、回收、保护、地址转换（虚拟内存）。
  • 文件系统：文件创建/读写/权限管理。
  • 设备管理：统一设备驱动接口。
  • 用户界面：CLI/GUI/Web 交互。
26Linux 下进程间通信方式概述？★★★★★

28概述一下进程调度★★★★★
一句话按调度算法分配 CPU 时间片：FCFS / SJF / 时间片轮转(RR) / 优先级，保证公平合理地共享 CPU。
展开：调度流程 + 四算法
flowchart LR A[就绪队列] --> B[调度器选进程] B --> C[分配 CPU 运行] C --> D[时间片到 / 阻塞] D --> A
  • FCFS：按到达顺序，先来先服务。
  • SJF：优先执行时间最短的作业。
  • RR：轮流分配固定时间片。
  • 优先级：高优先级先得 CPU。
29Linux 的任务调度介绍一下？★★★
一句话默认 CFS 按虚拟运行时间(vruntime)公平调度；实时策略 SCHED_FIFO/SCHED_RR；抢占式 + 多核亲和与负载均衡。
展开：五个要点
  • 调度器：按优先级、状态、策略决定谁得 CPU。
  • CFS：默认普通进程调度，运行时间短的优先（公平）。
  • 实时策略：SCHED_FIFO(先入先出)、SCHED_RR(时间片)、SCHED_IDLE、SCHED_BATCH。
  • 优先级：实时 1~99，普通 100~139；动态优先级由 CFS 调整。
  • 多核：亲和性调度 + 负载均衡迁移。
30详细介绍一下进程调度算法？★★★★★
一句话六种：FCFS、SJF、SRTN(最短剩余,抢占)、RR、优先级、MLFQ(多级反馈队列)；MLFQ 综合优先级+时间片最常用。
展开：六算法对比
算法描述优点缺点
FCFS按到达顺序、非抢占简单、适合长作业短作业饿死
SJF优先最短作业、非抢占平均等待最短长作业饥饿、依赖预测
SRTN优先剩余最短、抢占实时好长作业饥饿、抢占开销
RR固定时间片轮转公平时间片长短影响性能
优先级按优先级调度满足关键任务低优先级饥饿（需老化）
MLFQ多级队列，高优先级时间片短动态调整、兼顾长短实现复杂

MLFQ：高优先级队列分短时间片，用尽降级到低优先级队列（长时间片），动态避免饥饿。

31抢占式进程调度要怎么实现？★★★
一句话靠时钟中断 + 优先级抢占 + 内核调度器：触发中断→保存 PCB 上下文→调度器选新进程→切换并恢复。
展开：实现步骤
  1. 触发中断：定时器中断，或高优先级任务就绪。
  2. 保存当前进程状态：寄存器、PC 存入 PCB。
  3. 调用调度器：按算法选下一进程。
  4. 进程切换：CPU 控制权交新进程。
  5. 恢复上下文并运行。

33Linux 为什么分用户空间和内核空间？★★★
一句话为安全与稳定：用户态受限，只能经系统调用进内核；内核统一管资源，错误被隔离。
展开：交互流程 + 原因

  • 安全性：用户程序无法直接碰内核资源，防恶意破坏。
  • 稳定性：用户程序崩溃不影响内核。
  • 保护性：特权操作仅内核可执行。
  • 效率/资源管理：内核统一管资源，分工高效。
  • 错误隔离：用户错误被限制在用户空间。

35进程状态的切换你知道多少？★★★★
一句话三态：就绪⇄运行(调度/时间片耗尽)、运行→阻塞(等资源)、阻塞→就绪(资源满足)。
展开：状态切换图
flowchart TD A[就绪态] -- 调度器选中 --> B[运行态] B -- 时间片耗尽/被抢占 --> A B -- 等待资源 IO/锁 --> C[阻塞态] C -- 资源满足 --> A
  • 就绪→运行：调度器选中，分配 CPU。
  • 运行→就绪：时间片耗尽或被抢占。
  • 运行→阻塞：请求资源（I/O）不可用，主动放弃 CPU。
  • 阻塞→就绪：等待的资源就绪。
36多线程的执行顺序是怎样的？★★★
一句话由调度器动态决定，开发者无法完全控制；受优先级、调度算法、时间片、同步竞争、实时需求影响。
展开：五大影响因素
  • 线程优先级：高优先先调度。
  • 调度算法：RR、优先级、实时调度。
  • 时间片：影响响应与切换频率。
  • 同步与资源竞争：持锁等待影响顺序。
  • 实时任务：抢占普通线程。
37Windows 中进程执行完成后静态区的处理？★★★
一句话进程终止时 OS 统一回收全部内存（静态区、堆、栈、代码段），即使未显式 free 也会回收。
展开
  • 进程结束(ExitProcess/主函数返回)，OS 回收代码段、静态区、堆、栈等所有内存。
  • 静态区(全局/静态变量、常量)随之清除，不再占用资源。
  • 未显式释放的动态内存也会被回收，但不建议此不良习惯。
38单核 CPU 上的线程调度顺序？★★★★
一句话单核同时只跑一个线程，靠时间片轮转 / 优先级 / 抢占式 / 实时调度交替运行。
展开：四种调度方式
  • 时间片轮转：固定时间片轮流，公平。
  • 优先级调度：高优先级先执行，同优先级轮转。
  • 抢占式调度：更高优先级可中断当前线程。
  • 实时调度：满足严格时限，推迟非实时任务。
39线程优先级反转，如何解决？★★★★★
一句话高优先级被中优先级阻塞（因等低优先级持锁）；解决：优先级天花板(静态提权)或优先级继承(临时继承被阻塞者优先级)。
展开：定义 / 危害 / 解法
  • 反转：高优先级线程等低优先级释放锁，低优先级又因中优先级无法释放。
  • 危害：破坏实时性、调度逻辑紊乱，甚至崩溃。

两种解法

方法机制优点缺点
优先级天花板静态：申请资源时提到该资源所有线程中最高优先级简单、完全避免可能不必要提权、加开销
优先级继承动态：低优先级临时继承被阻塞者的优先级灵活、仅必要时调整实现复杂（嵌套资源）

40Linux 中断流程与处理操作？★★★
一句话硬件产生中断→控制器传给 CPU→保存现场→执行 ISR→清中断→恢复现场→返回；分上半部/下半部。
展开：中断时序
sequenceDiagram participant H as 硬件设备 participant C as 中断控制器 participant K as 内核/CPU H->>C: 产生中断信号 C->>K: 传入中断引脚 Note over K: 保存现场(PC/寄存器) K->>K: 跳转中断向量表执行 ISR K->>K: 清除中断标志 Note over K: 恢复现场 K-->>H: 中断返回 iret

  • 优先级：高优先级中断可抢占低优先级中断。
41保护现场保护什么东西？★★★

EBX 基址寄存器内存寻址基地址
ECX 计数器循环计数器(LOOP/REP)

  • SP：指向当前栈顶，可能切到内核栈需保存。
  • 保护现场：保存通用寄存器/PC/SP（及段、标志寄存器）→ 切内核栈。

一句话外中断=外部硬件异步触发（可屏蔽、按中断号）；异常=CPU 内部同步触发（除零/缺页，通常不可屏蔽）。

43中断和轮询介绍一下★★★★★
一句话中断=事件驱动、外设主动请求、实时好、开销低；轮询=CPU 主动逐设备查询、简单但大量浪费 CPU。

中断流程

  1. 外设发中断请求；CPU 检测是否允许/被屏蔽；优先级判断。
  2. 保护现场 → 跳转 ISR → 恢复现场 → 返回。

64解释一下 mmap 的 API★★★★
一句话mmap 把文件/设备映射到进程地址空间，让进程用内存指针直接读写文件，省去 read/write 两次拷贝；用 munmap 解除映射。
展开：函数原型 + 参数表 + 示例

函数原型

void *mmap(void *addr, size_t length, int prot, int flags, int fd, off_t offset);
int  munmap(void *addr, size_t length);   // 解除映射

参数说明

参数含义常见取值
addr映射起始地址NULL（由内核自动分配）
length映射大小（字节）页对齐的整数
prot访问权限PROT_READ / PROT_WRITE / PROT_EXEC / PROT_NONE
flags映射类型MAP_SHARED（共享）/ MAP_PRIVATE（私有，写时拷贝）
fd要映射的文件描述符由 open() 返回
offset文件内偏移通常为 0（需页对齐）

示例代码

#include <sys/mman.h>
#include <fcntl.h>
#include <unistd.h>
#include <stdio.h>

int main() {
    int fd = open("test.txt", O_RDWR);
    if (fd == -1) { perror("open"); return -1; }

    size_t length = 4096;
    char *map = mmap(NULL, length, PROT_READ | PROT_WRITE, MAP_SHARED, fd, 0);
    if (map == MAP_FAILED) { perror("mmap"); close(fd); return -1; }

    map[0] = 'H';                  // 直接改映射内存 = 写文件
    if (munmap(map, length) == -1) // 解除映射
        perror("munmap");
    close(fd);
    return 0;
}
65Tasklet 和 Workqueue 的底层区别★★
一句话Tasklet 跑在软中断上下文、不能睡眠、优先级高；Workqueue 跑在进程上下文、可睡眠、更灵活但慢。快任务用 Tasklet，耗时任务用 Workqueue。
展开：定义 + 底层区别表
  • Tasklet：轻量级软中断机制，把部分中断处理从硬中断挪到软中断上下文完成；不能睡眠、不能调阻塞函数，适合快速、非阻塞的延迟任务。
  • Workqueue：在进程上下文中，由内核线程执行；允许睡眠，适合多次 I/O、耗资源等复杂任务。

底层区别

调度方式由硬中断处理程序调度，优先级高由内核线程调度，优先级取决于调度器
适用场景短期、简单、实时性高的任务复杂、耗时（文件系统、多次 I/O）
性能/灵活性快，但功能受限相对慢，但更灵活
66阻塞与休眠原理★★
一句话阻塞=被动等事件（如 I/O 完成、信号），挂起且不占 CPU；休眠=主动让出 CPU 等时间/条件。前者事件驱动，后者时间控制。
展开：定义 + 区别表
  • 阻塞：等事件发生时任务被挂起、进入睡眠，从运行队列移除、不占 CPU；事件到来或超时后被唤醒重入队列。常用 wait_event() / wait_event_interruptible()。
  • 休眠：任务主动让出 CPU 进入睡眠，等指定时间或条件满足再被唤醒。常用 msleep() / ssleep()。

主要区别

等待对象事件（I/O、信号）时间/条件
CPU 占用不占用不占用
适用场景事件驱动型任务时间控制型（简单延迟）
67MCU 上如何设计用户态和内核态★★
一句话高端 MCU 用硬件特权级（特权/非特权模式）划分；低端 MCU 无硬件支持，靠软件模拟（任务隔离 + 系统调用 + 权限管理）实现。
展开：两条路线

① 硬件支持（如 ARM Cortex-M 特权级）

  • 特权模式：可访问全部资源（内核内存、外设），内核与驱动运行于此。
  • 非特权模式：只能访问有限资源、禁止特权指令，用户任务运行于此，经系统调用与内核交互。
  • 流程：启动 → 特权模式加载内核 → 用户任务切到非特权模式受限运行 → 需特权操作时发系统调用 → 内核完成后返回。

② 软件模拟（低端 MCU）

  • 任务隔离：调度器把用户任务与内核任务隔离，防止用户任务直接访问内核数据/硬件。
  • 系统调用机制：定义一组接口，用户任务只能经系统调用请求内核服务，内核验证权限后执行。
  • 权限管理：严格限制用户任务对系统资源的访问范围。
68如何评估操作系统的实时性？如何测算中断响应时间★★
一句话评估靠 4 指标：调度延迟、中断延迟、任务响应时间、抖动；测中断响应时间可用硬件计时器或软件时间戳。

评估实时性的四个指标

指标含义说明
调度延迟任务就绪 → 被调度上 CPU 的时间取决于调度算法、优先级管理、任务复杂度
中断延迟硬件中断触发 → ISR 开始执行的时间受中断屏蔽时间、优先级配置影响

  • 软件测量：中断触发前记基准时间戳 → ISR 开始再记时间戳 → 比较两时间戳求差值。
69x86 架构概述★
一句话x86 是 Intel 的 CISC 处理器架构，从 8086(16位，段式) → IA-32(32位，分页) → x86-64(AMD 扩展，64位) 演进，向后兼容旧软件。
展开：定义 + 发展史
  • x86 由 Intel 于 1978 年随 8086 微处理器推出，最初是 16 位，后扩展为 32 位（IA-32）与 64 位（x86-64），靠复杂指令集（CISC）支撑多种计算任务，并向后兼容早期软件。

发展历史

处理器关键特性
808616 位，1MB 寻址，段式内存管理（段地址 + 偏移）
80286引入保护模式，多任务，寻址 16MB
80386首个 32 位，虚拟内存最大 4GB，引入分页机制
80486集成 FPU（浮点单元）+ 一级缓存 L1
Pentium支持 SMP 对称多处理与超标量架构
x86-64AMD 提出的 64 位扩展，地址空间可达 16EB，更多通用寄存器，成为现代标准
