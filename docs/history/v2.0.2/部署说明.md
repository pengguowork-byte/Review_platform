# 嵌入式校招八股 · AI 分级复习系统 部署说明

> 适用版本：v2.0.2 修复版（2026-09-30）
> 适用文件：server.js、嵌入式校招八股_总览.html
> 最后校验日期：2026-09-30（V2.2：新增「文件导入与内容提取」模块，部署要点见 §8）

---

## 1. 系统组成与文件清单

| 文件 | 作用 |
|---|---|
| `server.js` | **唯一需要运行的服务**。Node 单文件，同时负责静态托管笔记 + 代理 AI 判分 |
| `嵌入式校招八股_总览.html` | 总览页入口（296 题），需通过 `server.js` 访问 |
| `C++_八股.html` / `操作系统_八股.html` 等 | 分章独立页，可单独双击打开（但 AI 判分不可用） |

**部署约束（务必先看）**：

1. **页面必须由 `server.js` 托管**。前端用相对路径调用 `/api/judge` 与 `/api/quiz`，所以判分请求发往的是「页面所在源」。用 `file://` 双击打开或另起 `python -m http.server` 都会导致判分不可用（页面会提示「判分服务未连接」）。
2. **无需 npm install**。`server.js` 只用 Node 内置模块（`http`/`fs`/`path`/`url` + 全局 `fetch`），无第三方依赖。
3. 静态根目录就是脚本所在目录（`__dirname`），换机器部署时把整个文件夹拷过去即可。
4. **导入提取模块需额外联网**（见 §8）：浏览器端懒加载 pdf.js / mammoth / tesseract.js / SheetJS（jsdelivr CDN），OCR 还需下载中文识别包（约 20MB）。离线时该模块的解析与生成不可用，仅可查看已提取结果；复习判分不受影响。

## 2. 环境要求

| 项 | 要求 | 说明 |
|---|---|---|
| Node.js | **18.0+**（推荐 20/22/24 LTS） | 依赖全局 `fetch` 与 `AbortController`；Node 16 会直接报 fetch is not defined |
| 操作系统 | Windows / macOS / Linux 均可 | 本文以 Windows PowerShell 为主，附 bash 命令 |
| 网络 | 能访问你配置的上游 API | 默认 `https://api.deepseek.com` |
| 网络（导入提取） | 能访问 `cdn.jsdelivr.net`、`tessdata.projectnaptha.com` | 提取模块懒加载 pdf.js / mammoth / tesseract.js（含中文识别包）/ SheetJS，见 §8 |

```powershell

```

## 3. 快速开始（3 步跑起来）

### 第 1 步：配置 API Key（三选一）

**方式 A —— 环境变量（推荐，Key 不落磁盘）**

```powershell
$env:DEEPSEEK_API_KEY="sk-你的真实Key"
```

**方式 B —— `deepseek.key` 文件（免每次设变量）**

把包里的 `deepseek.key.example` 复制一份改名为 `deepseek.key`，首行写入 Key，保存即可：

```
sk-你的真实Key
# 这一行往后的注释会被自动跳过，不影响读取
```

> 解析容错（v2.0.2）：空行与 `#` / `;` 注释行自动跳过（直接从模板改名也能读到第 10 行的 Key）；
> 「Key + 同行备注」只取第一段；Key 含中文/全角字符会返回可读的中文报错而不是英文天书。

**方式 C —— 永久写入当前用户环境变量（设一次，长期生效）**

```powershell
[System.Environment]::SetEnvironmentVariable('DEEPSEEK_API_KEY','sk-你的真实Key','User')
```

> 方式 C 设置后**必须重开一个 PowerShell 窗口**才会生效。

优先级：**环境变量 > `deepseek.key` 文件**。两者都配了以环境变量为准。

### 第 2 步：启动服务

```powershell
cd <解压目录>            # 例如 d:\study 或 D:\Tools\嵌入式八股复习系统_v2.0.2
node server.js            # 默认 8000 端口
node server.js 9000       # 指定端口
```

> 端口被占用时不再退出，而是**自动顺延**（8000 → 8001 → …，最多 10 个），实际端口同时写入同目录 `.server-port`，供 `启动.cmd` 打开正确的浏览器地址；`EADDRINUSE` 全部耗尽才退出并提示手动换端口。

看到这样的输出即成功：

```
==============================================
  嵌入式校招八股 · AI 判分服务已启动
==============================================
  本页入口   http://localhost:8000/嵌入式校招八股_总览.html
  快捷入口   http://localhost:8000/review
  局域网     http://<你的IP>:8000/   （手机连同一 WiFi 时可用）
  API Key    已就绪（sk-1a****）
==============================================
```

若显示 `API Key 未配置！`，说明 Key 没读到，见第 10 节排查。

### 第 3 步：打开页面

浏览器访问任一入口：

- http://localhost:8000/review
- http://localhost:8000/嵌入式校招八股_总览.html

侧边栏应显示 **`AI 自测 0 次 · 平均覆盖 0%`**（而非红色的「判分服务未连接」）。

## 4. `DEEPSEEK_BASE_URL` 配置详解

### 4.1 它是什么

`DEEPSEEK_BASE_URL` 用来覆盖 **OpenAI 兼容端点的完整地址**，默认指向 DeepSeek 官方：

```
https://api.deepseek.com/chat/completions
```

服务端代码（`server.js:38`）读取逻辑：

```js
const UPSTREAM = process.env.DEEPSEEK_BASE_URL || 'https://api.deepseek.com/chat/completions';
```

### 4.2 什么时候需要改

| 场景 | 是否需要改 |
|---|---|
| 直接用 DeepSeek 官方 Key | 不需要（用默认值） |
| 走自建网关/中转（如 OneAPI、New API） | **需要** |
| 用 vLLM / Ollama / LM Studio 本地部署模型 | **需要** |
| 公司统一出口代理、海外网络需中转 | **需要** |
| 只想换模型名（如 `deepseek-reasoner`） | 见 4.5，目前需改代码 |

### 4.3 三种配置方式

**方式 A —— 与 Key 一起用临时变量（联调最灵活）**

```powershell
$env:DEEPSEEK_API_KEY="sk-你的key"
$env:DEEPSEEK_BASE_URL="http://127.0.0.1:3000/v1/chat/completions"
node server.js
```

**方式 B —— 永久写入用户环境变量**

```powershell
[System.Environment]::SetEnvironmentVariable('DEEPSEEK_BASE_URL','https://your-gateway.com/v1/chat/completions','User')
```

设置后**重开终端**生效。bash 用户用 `export DEEPSEEK_BASE_URL=...` + 写入 `~/.bashrc`。

**方式 C —— 写进启动脚本（团队协作推荐）**

在解压目录新建 `启动.cmd`（**另存为「UTF-8」编码**，配合首行 `chcp 65001` 才能正确显示中文）：

```bat
@echo off
chcp 65001 >nul
set DEEPSEEK_API_KEY=sk-你的key
set DEEPSEEK_BASE_URL=https://your-gateway.com/v1/chat/completions
node server.js
pause
```

双击即可运行。

### 4.4 地址格式要求（最容易踩坑）

1. **必须是完整路径，包含 `/chat/completions` 结尾**，不能只填域名或 `/v1`。
2. **结尾不要带斜杠**，否则会变成 `/chat/completions/` 导致部分网关 404。
3. 上游必须**返回 OpenAI 格式**：`{ "choices": [ { "message": { "content": "..." } } ] }`。
4. 上游必须支持 **`response_format: {"type":"json_object"}`**，否则判分解析会失败。
5. 鉴权方式固定为 **`Authorization: Bearer <你的Key>`**。

常见端点写法参考：

| 部署方式 | `DEEPSEEK_BASE_URL` 示例 |
|---|---|
| DeepSeek 官方 | 不设置（默认 `https://api.deepseek.com/chat/completions`） |
| OneAPI / New API | `https://网关域名/v1/chat/completions` |
| Ollama | `http://localhost:11434/v1/chat/completions` |
| LM Studio | `http://localhost:1234/v1/chat/completions` |
| vLLM | `http://localhost:8000/v1/chat/completions` |

### 4.5 已知限制

- **模型名固定为 `deepseek-chat`**（`server.js:39`）。换成非 DeepSeek 模型时需同步改这一行，或在你自己的网关上把模型名映射成 `deepseek-chat`。
- `max_tokens` 固定 900、`temperature` 判分 0.2 / 出题 0.5、超时 60 秒。这些是当前试出的稳定值，改模型时如遇截断可自行调整。
- 上游不可用时，前端判分会弹出具体错误；**手动标记等级仍然可用**（右侧「另一个篮子」）。

## 7. 多设备同步（手机 ↔ 电脑）

### 7.1 为什么需要手动同步

复习进度存在**每个浏览器各自的 localStorage** 里，key 为 `eb-review-system-v1`。因此：

| 场景 | 是否共享进度 |
|---|---|
| 电脑 Chrome vs 电脑 Edge | 否，各自独立 |
| 电脑 vs 手机浏览器 | 否，各自独立 |
| 手机浏览器 vs 微信内置浏览器 | 否，各自独立 |
| 清除浏览器数据 | 进度归零，不可恢复 |

所以「导出进度 → 导入进度」是唯一的同步手段。**建议每天复习完做一次双向同步。**

### 7.2 操作方法

两个按钮在正文顶部工具栏（搜索框右侧）：

**电脑 → 手机**

1. 电脑上点 **导出进度**，下载得到 `嵌入式八股-复习进度-YYYYMMDD-HHMM.json`。
2. 通过微信文件传输助手 / QQ / 网盘把该文件发到手机。
3. 手机浏览器访问 `http://<电脑IP>:8000/review`，点 **导入进度 → 选择文件**，选中刚收到的 JSON。
4. 看到预览数字（新增 / 合并更新 / 无变化）后点 **确认导入**。

**手机 → 电脑**

1. 手机上点 **导出进度**（手机浏览器会下载文件）。
2. 把该文件发到电脑。
3. 电脑上点 **导入进度 → 选择文件** 导入。

> 手机上不方便选文件时，可用 **粘贴内容** 标签页：在另一台设备上导出后，用文本编辑器打开 JSON 全选复制，粘贴进来点「解析」。

### 7.3 合并规则（重要，先看再导）

同步不是简单地「谁覆盖谁」，而是以 **history（复习历史）为唯一事实来源**做合并：

| 情况 | 处理方式 |
|---|---|
| 某题只在一方有记录 | 直接采用，计为「新增」 |
| 双方都有记录 | 以**证据更多**的一方（自测次数 + 历史条数）为基底 |
| 基底缺少的事件 | 把另一方新增的历史条目**按时间顺序重放**到基底状态上 |
| 重复事件（时间戳、等级、类型都相同） | 自动去重，不重复计数 |
| 旧快照（内容是本机历史的前缀） | 判为「无变化」，**不会回退你的新进度** |
| 旧版四等级数据（`level: "wrong"`） | 自动迁移为「忘记了」 |

一句话：**最新的那次复习结果生效，两次复习之间的所有记录都保留，不会互相覆盖丢失。**

### 7.4 已知限制

1. **依赖设备时钟正确**。合并以时间戳判断新旧，如果某台设备时间设置错误（快/慢几年），可能让旧的复习结果覆盖新的。养成「手机开自动同步时间」的习惯即可避免。
2. **同一题在两台设备上分别复习过**，会记为两次真实复习（这才是符合事实的），历史条数和自测次数会累加。
3. 历史最多保留 **每条题 60 条**记录，超出后自动丢弃最旧的（不影响当前等级与排期）。
4. 导出的文件仅包含**有进度的题**，未自测过的题不会进入文件，因此文件通常很小。

## 8. 导入提取模块 · 部署要点

该模块把 PDF / Word / 图片转成「知识点 + 题库」。**文件全程在浏览器本地解析，不上传服务器**；只有「生成知识点 / 生成题库」两步调用 LLM，走 `server.js` 代理。

### 8.1 服务端新增端点（server.js）

| 端点 | 请求 | 上限保护 | 失败行为 |
|---|---|---|---|
| `/api/kpoints` | `{chunks:[{text,page}]}` | 单次最多 **30 块**，返回最多 **25 条**知识点；`max_tokens=1500`、`temperature=0.3` | chunks 为空 → 400；模型无有效输出 → 500 |
| `/api/qbank` | `{chunks, points?}` | 最多 **20 块 + 20 条**输入，返回最多 **20 题**；`max_tokens=2000`、`temperature=0.4` | 两者皆空 → 400；模型无有效输出 → 500 |

两个端点复用同一套 Key 与 `DEEPSEEK_BASE_URL` 配置，**无需额外环境变量**。请求体上限已随分块文本上调：`MAX_BODY = 2MB`（判分/出题的老限制是 512KB）。

### 8.2 浏览器端 CDN 依赖（离线即不可用）

| 库 | 版本 / 来源 | 用途 | 加载失败时的表现 |
|---|---|---|---|
| pdf.js | `pdfjs-dist@4.10.38`（jsdelivr） | PDF 逐页取字 + 渲染扫描页 | PDF 提取失败，文件标 `err` |
| mammoth | `mammoth@1.8.0`（jsdelivr） | .docx 提取文本 | docx 提取失败，文件标 `err` |
| tesseract.js | `tesseract.js@5.1.1`（jsdelivr） | 图片 / 扫描页 OCR | OCR 失败，文件标 `err` |
| SheetJS | `xlsx@0.18.5`（jsdelivr） | Excel 导出 | **自动回退 CSV** 并 toast 提示（0.18.5 是 jsdelivr 上可用的最高版，0.20.x 会 404） |
| tessdata | `tessdata.projectnaptha.com`（chi_sim，约 20MB） | 中文 + 英文识别语言包 | OCR 失败，文件标 `err` |

> 首次使用 OCR 会下载约 20MB 语言包，属正常耗时；同一浏览器第二次起有缓存。

### 8.3 存储与护栏

- 提取结果存 **IndexedDB**（库名 `eb-extract-v1`，四个 store：files / blocks / points / questions），**随浏览器隔离**，不与手机共享；换设备靠导出 JSON 搬运。
- 护栏：单文件 **50MB** 上限；魔数校验（伪装扩展名会被拒）；批量导入**并发 2**；OCR **单文件最多 30 页**、渲染 **150dpi**；相邻同源块按 **2000 字符**合并；结果编辑 **400ms 防抖**落库。
- 性能指标：≤50MB 文件处理 ≤30s；文本提取准确率 ≥90%；知识点识别准确率 ≥85%（见《测试用例.md》§3.8）。

### 8.4 已知限制

1. **`file://` 双击打开时**，本地解析（PDF / docx / OCR / 分块 / 导出）可用，但「生成知识点 / 生成题库」两个 LLM 步骤被禁用并提示——必须由 `server.js` 托管。
2. **旧版 `.doc`（OLE2 格式）不支持**，页面会给出「另存为 .docx」友好提示。
3. **扫描页 / 手写体 OCR 识别率有限**（tesseract 引擎能力上限）：印刷体扫描页效果好，潦草手写可能只识别出部分关键词；知识点生成前建议人工核对。
4. OCR 页数超过 30 页的文件会跳过 OCR 并标 `warn`，其余页正常提取。

## 9. 部署后自检清单

```powershell
# 1. 服务是否活着、Key 是否读到
curl.exe -s http://localhost:8000/api/health
# 期望：{"ok":true,"hasKey":true,"model":"deepseek-chat"}

# 2. 静态托管是否正常
curl.exe -s -o NUL -w "%{http_code}`n" http://localhost:8000/%E5%B5%8C%E5%85%A5%E5%BC%8F%E6%A0%A1%E6%8B%9B%E5%85%AB%E8%82%A1_%E6%80%BB%E8%A7%88.html
# 期望：200

# 3. 快捷入口是否跳转
curl.exe -s -o NUL -w "%{http_code} -> %{redirect_url}`n" http://localhost:8000/review
# 期望：302 -> http://localhost:8000/嵌入式校招八股_总览.html

# 4. 判分链路是否通（用一句真话测试）
curl.exe -s -X POST http://localhost:8000/api/judge -H "Content-Type: application/json" -d "{\"mode\":\"quick\",\"question\":\"new 和 malloc 的区别\",\"reference\":\"new 是运算符，会调用 operator new 分配内存并调用构造函数，失败抛 bad_alloc；malloc 只分配内存不构造对象，失败返回 NULL，且需指定字节数。\",\"answer\":\"new 会调用构造函数，malloc 不会，new 失败抛异常\"}"
# 期望：{"ok":true,...,"coverage":xx,"level":"skilled",...}

# 5. 提取模块服务端端点（空输入应被 400 拒绝）
curl.exe -s -X POST http://localhost:8000/api/kpoints -H "Content-Type: application/json" -d "{\"chunks\":[]}"
# 期望：{"ok":false,"error":"chunks 为空，没有可抽取的文本"}
curl.exe -s -X POST http://localhost:8000/api/qbank -H "Content-Type: application/json" -d "{\"chunks\":[],\"points\":[]}"
# 期望：{"ok":false,"error":"既没有知识点也没有文本块，无法出题"}

# 6. 提取模块 CDN 是否可达（离线时导入提取功能不可用）
curl.exe -s -o NUL -w "%{http_code}`n" https://cdn.jsdelivr.net/npm/xlsx@0.18.5/dist/xlsx.full.min.js
# 期望：200（404 说明被镜像劫持或版本写错，Excel 导出会回退 CSV）
```

第 4 步若返回 `{"ok":false,"error":"DeepSeek 返回 401：..."}`，说明链路通了、Key 无效；返回 `无法连接` 则是 `DEEPSEEK_BASE_URL` 写错。

## 10. 常见问题排查

| 现象 | 原因 | 解决 |
|---|---|---|
| 侧边栏红色「判分服务未连接」 | `file://` 打开 / 服务没起 / 端口不对 | 用 `http://localhost:8000/review` 访问 |
| 启动就报 `listen EADDRINUSE` | 端口被占 | `node server.js 9000` |
| `fetch is not defined` | Node 版本低于 18 | 升级 Node |
| 判分返回「服务端未配置 DEEPSEEK_API_KEY」 | Key 没读到 | 检查变量名拼写、是否重开终端、或改用 `deepseek.key` |
| 判分返回 `DeepSeek 返回 401` | Key 错误 / 网关鉴权方式不同 | 换 Key；确认网关接受 `Authorization: Bearer` |
| 判分返回 `DeepSeek 返回 404` | `DEEPSEEK_BASE_URL` 少了 `/chat/completions` 或多了尾斜杠 | 按 4.4 节格式修正 |
| 判分返回「模型返回的不是合法 JSON」 | 上游不支持 `json_object` 模式 | 换支持该参数的上游，或在网关上做格式兜底 |
| 判分返回「请求体过大」 | 某题标准答案超长 | 已限制 2MB（分块文本需要更大 body），正常题库不会触发 |
| 导入 .pdf / .docx / 图片没反应或标 err | 没联网，CDN 库没加载；或文件是伪装的扩展名 | 联网后刷新；确认文件头真实（魔数校验会拒绝改扩展名的文件） |
| Excel 导出下载下来是 CSV | jsdelivr 不可达或 `xlsx@0.18.5` 404 | 见 §8.2；确认 CDN 可达后重试，数据不丢 |
| 点「生成知识点 / 生成题库」提示不可用 | 用 `file://` 打开的页面 | 必须经 `server.js` 访问（见 §8.4） |
| 扫描版 PDF 提取出来是空的 | 页文本 < 50 字符才触发 OCR；潦草手写识别率有限 | 换更清晰的扫描件；OCR 单文件上限 30 页，超出会跳过 |
| 导入 .doc 被拒绝 | OLE2 旧格式，需先「另存为 .docx」 | Word 里另存为 .docx 再导入 |
| 提取结果换设备看不见 | 存在浏览器 IndexedDB，不随账号同步 | 用结果区「导出 JSON」搬运，或见 §8.3 |
| 手机访问不了 | 防火墙 / 不同 WiFi / IP 填错 | 见第 5 节 |
| 导入时提示「未找到 cards 字段」 | 选错文件，或文件被编辑改坏了 | 重新在另一台设备点「导出进度」，别手改内容 |
| 导入后等级变低了 | 另一台设备确实后来复习过且判得更差 | 属正常，合并以最新复习为准；可在「另一个篮子」里手动标回 |
| 导入后 `quizzes` 数字变大 | 同一题在两台设备上分别复习过 | 属正常，两次都是真实复习 |
| 页面正常但流程图显示源码 | 没联网，mermaid.js CDN 没加载 | 联网后刷新 |

## 11. 安全注意事项

1. **Key 只存在于服务端进程**。`server.js` 不向页面返回 Key，`/api/health` 只回 `hasKey` 布尔值。
2. **不要把 `deepseek.key` 提交到 git**。建议在项目里加一行 `.gitignore`：
   ```
   deepseek.key
   ```
3. **不要把 Key 写进 HTML**。曾有「浏览器直连 + 前端填 Key」的方案，因 CORS 被 DeepSeek 拦截且 Key 会暴露在前端源码里，已放弃。
4. 本服务**默认对所有来源开放接口**（CORS `*`）且**无鉴权**，仅适合本机/家庭局域网自用。若部署到公网，务必在前面加一层鉴权（反向代理 + Basic Auth /  Token），否则等于公开你的 Key。
5. **导入的文件不会上传服务器**：PDF / Word / 图片全部在浏览器本地解析（PDF.js / mammoth / tesseract.js），发往服务端的只有提取出的文本块，不存在文件泄露面。
