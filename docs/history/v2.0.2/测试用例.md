## 3. 系统规格基线（用例判定依据）

> 以下常量全部从源码提取，作为所有「预期结果」的判定依据。

### 3.1 五级判定标准

| 等级 | `level` 值 | 覆盖率 coverage | CSS 类 | 颜色 | 描述 |
|---|---|---|---|---|---|
| 未记忆 | `unseen` | — | `lv-unseen` | `#64748b` | 尚未开始自测 |
| 忘记了 | `forgotten` | `< 30` | `lv-forgotten` | `#dc2626` | 覆盖率 < 30%，基本想不起 |
| 模糊 | `fuzzy` | `30–60` | `lv-fuzzy` | `#d97706` | 覆盖率 30~60%，零散记得 |
| 熟练 | `skilled` | `60–85` | `lv-skilled` | `#059669` | 覆盖率 60~85%，大体能讲 |
| 完全掌握 | `mastered` | `≥ 85` | `lv-mastered` | `#2563eb` | 覆盖率 ≥ 85%，完整复述 |

**附加规则**（`server.js` judge Prompt）：
- **A**：若 `accuracy < 40`（存在明显事实错误），等级最高只能为 `fuzzy`，不得给 `skilled` / `mastered`。
- **B**：复述为空、跑题、只抄题目本身 → `coverage = 0`，等级 `forgotten`。
- **C**：口语化、顺序颠倒、用词不同但意思对 → 算覆盖，不苛刻。

**边界取值表**（可直接作为用例数据）：

| coverage | 预期 level | coverage | 预期 level |
|---|---|---|---|
| 0 | forgotten | 60 | skilled |
| 29 | forgotten | 70 | skilled |
| 30 | fuzzy | 84 | skilled |
| 45 | fuzzy | 85 | mastered |
| 59 | fuzzy | 100 | mastered |

**夹紧规则**：`coverage` 越界（如 250）夹紧为 100；负数夹紧为 0。

### 3.2 数据模型

| 字段 | 类型 | 含义 | 默认 |
|---|---|---|---|
| `level` | string | 五级之一 | `unseen` |
| `interval` | number | 当前间隔（天） | 0 |
| `ease` | number | 难度系数，1.3–3.0 | 2.5 |
| `due` | number | 下次到期时间戳（ms） | 0 |
| `gate` | number | 达标计数，≥2 即毕业 | 0 |
| `stage` | number | 毕业后长期间隔序号 | 0 |
| `lapses` | number | 翻车次数（判为忘记了 +1） | 0 |
| `quizzes` | number | AI 自测次数（手动标记不增） | 0 |
| `restudy` | boolean | 是否处于强制重学 | false |
| `lastScore` | number | 最近一次覆盖率 | — |
| `history` | array | 事件流水，最多 60 条 | — |

`history` 条目：`{ ts, result, level, coverage, accuracy, interval }`
- `result`：`'quiz'`（AI 判分）或 `'manual-<level>'`（手动标记）或 `'manual-unseen'`（标记为未记忆）

### 3.3 间隔重复 + 毕业门控算法

```
毕业条件：连续 2 次（gate >= 2）自测达到「熟练」及以上

判为「忘记了」：
  gate = 0; interval = 0; due = now; restudy = true; stage = 0
  ease = max(1.3, ease - 0.2);  lapses += 1

判为「模糊」：
  interval = interval >= 7 ? 7 : max(1, round(interval * 3))   // 1 → 3 → 7 天
  due = now + interval * 86400000
  ease = max(1.3, ease - 0.1);  restudy = false

判为「熟练」或「完全掌握」：
  gate += 1;  restudy = false
  ease = min(3.0, ease + 0.05 | +0.1)      // skilled +0.05 / mastered +0.1
  if (gate >= 2) {                          // 毕业 → 长期间隔
      stage += 1
      interval = (mastered ? MASTERED_TRACK : SKILLED_TRACK)[min(stage-1, len-1)]
      due = now + interval * 86400000
  } else {                                  // 差最后一次达标 → 当天补
      interval = 1; due = now
  }

长期间隔表：
  SKILLED_TRACK  = [7, 15, 30, 60]
  MASTERED_TRACK = [30, 60, 120]

到期复查：已毕业题到期后 gate 归零，需重新证明 2 次才再毕业
```

### 3.4 队列过滤条件

| 队列 | 判定函数 | 条件 |
|---|---|---|
| 另一个篮子（入队） | `inQueue(c)` | `level` 存在且 `!== 'unseen'` 且 `gate < 2` |
| 复习模式（显示） | `inQueue(c) && isDue(c)` | 入队且 `due <= Date.now()` |
| 到期 | `isDue(c)` | `level` 非空非 `unseen` 且 `due > 0` 且 `due <= now` |

篮子排序：按 `due` 升序（最紧急在前）。

### 3.5 导出文件格式

```jsonc
{
  "app": "eb-review",
  "version": 2,
  "exportedAt": "2026-09-30T10:27:00.000Z",   // ISO 8601
  "source": "127.0.0.1",                       // location.hostname
  "summary": { "total": 296, "exported": 2, "quizzes": 2, "avgScore": 80 },
  "cards": { "<卡片ID>": { /* 与数据模型一致 */ } }
}
```

规则：**只导出 `level !== 'unseen'` 的卡片**；文件名 `嵌入式八股-复习进度-YYYYMMDD-HHMM.json`。

### 3.6 导入合并算法

```
对每张卡片 cid：
  1. 原值经 normalizeCard 归一化（wrong → forgotten；history 中 level 非法的条目剔除）
  2. 本机无此卡            → added（新增）
  3. 与本机完全相同           → unchanged
  4. 取证据权重 base：
       evidence(c) = (quizzes || 0) + (history ? history.length : 0)
       base = evidence(本机) >= evidence(导入) ? 本机 : 导入
       other = 另一方
  5. replayExtra：把 other 中 base 没有的事件（按 ts|result|level 判重）
       按 ts 升序重放到 base 上，每条调用 applyVerdict
 6. 重建完整时间线（顺序、去重、截断 60 条）
 7. 结果与本机相同 → unchanged；否则 → merged
```

**预览统计**：`新增 / 合并更新 / 无变化` 三个数字分别对应 `added / merged / unchanged`。
**脏数据**：`cards` 中值为 `null` 或非对象的条目被过滤并跳过。

### 3.7 服务端接口

| 接口 | 方法 | 请求 | 响应 |
|---|---|---|---|
| `/api/health` | GET | — | `{ok:true, hasKey:bool, model:"deepseek-chat"}` |
| `/api/judge` | POST | `{question, reference, answer, mode}` | `{level, coverage, accuracy, missed[], wrong[], comment, next}` |
| `/api/quiz` | POST | `{question, reference}` | `{questions:[{q,a}×3]}` |
| `/api/kpoints` | POST | `{chunks:[{text,page}]}` | `{points:[{id,type,title,content,page,confidence}]}`，空 chunks 400 |

| 常量 | 值 | 含义 |

**性能指标**：≤50MB 文件处理 ≤30s；文本提取准确率 ≥90%；知识点识别准确率 ≥85%。

### D-03 语义说明

重放规则为「按 `ts` 升序重放，最新判分生效」。手动标记生成的事件 `ts` 为当前时刻，必然晚于导入文件中的历史事件，因此最终取手动标记的等级。

**结论**：这是符合直觉的行为——用户在当前设备上亲手按下的判断，理应优先。若需改为「导入方胜出」，应反向重放（以导入为基准重放本机事件），但会更容易误伤本机的新进度，**不建议**。

## 11. 通过标准

1. **分级体系**：五级边界（29/30、59/60、84/85）全部正确；准确率 <40 封顶生效；视觉标识可辨。

4. **强制重学**：判忘了即锁输入，回顾答案后才可再测。
5. **进度跟踪**：每次复习记录 `ts/result/level/coverage/accuracy/interval`；刷新不丢。
6. **多设备同步**：三路径导入生效；幂等；双向收敛；旧等级自动迁移；损坏输入有明确报错。
7. **响应式**：375px 无横向溢出，弹窗与统计区不塌陷。
8. **稳定性**：全部 P0 用例通过，无已知 P0 级缺陷。
9. **导入提取**：四类拒绝全部生效（魔数 / 50MB / 扩展名 / 旧 .doc 提示）；PDF 数字页直接提取、扫描页 OCR 命中关键词；知识点 5 类型白名单 + 低置信度高亮；题库三题型且选择题保留 4 选项；JSON / CSV（BOM）/ xlsx（PK 头）三格式导出；刷新后四 store 数据完整恢复。
