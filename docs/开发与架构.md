# 模块化开发说明

## 文件职责

```text
index.html                     页面外壳、弹窗与工具栏
assets/css/app.css             原有布局与组件样式
assets/css/library.css         分类、专题和题库导入样式
assets/data/library.js         build 生成的离线兼容题库
assets/js/library.js           分类、题库校验、渲染、导入
assets/js/library-preferences.js 最近五个模块与自命名偏好
assets/js/knowledge-dialog.js   添加知识的统一入口与三种添加方式
assets/js/search.js            分类 / 专题 / 搜索 / 复习联合过滤
assets/js/navigation.js        侧栏目录折叠
assets/js/review-engine.js     纯复习算法、历史合并；可在 Node 单独测试
assets/js/review-ui.js         等级按钮、AI 自测、复习统计与篮子
assets/js/sync.js              复习进度导入导出、预览与合并
assets/js/extraction.js        提取工作台状态、队列、生成、编辑
assets/js/extract-storage.js   IndexedDB 读写
assets/js/extract-parsers.js   PDF / DOCX / 图片 OCR、校验、分块
assets/js/extract-exports.js   JSON / CSV / Excel / 复习题库导出
assets/js/bootstrap.js         最终过滤与可选流程图库加载
server.js                      HTTP 入口、启动、端口重试与关闭
server/api.cjs                 AI 接口校验、调用与结果归一化
server/ai-client.cjs           Key 读取、模型配置、上游请求与超时
server/prompts.cjs             跨学科出题、判分、提取提示词
server/http-utils.cjs          请求体和 JSON 响应
server/static.cjs              公共资源白名单与静态托管
data/library.json              知识类型 / 专题清单
data/subjects/*.json           每个内置专题的富文本内容
scripts/build.cjs              校验内置 ID、生成题库与兼容入口
scripts/launch.cjs             等待服务就绪后打开浏览器
tests/core.test.cjs            算法、合并、API、资源和权限回归
archive/                       拆分前源码与迁移脚本，仅作参考
```

浏览器模块使用显式依赖的工厂函数和少量命名空间；核心算法支持 CommonJS 与浏览器双环境。暂时不用 npm 打包工具，是为了保留便携发布和 file:// 浏览能力。模块加载顺序固定于页面底部：题库 → 算法 → 分类渲染 → 搜索 / 目录 → 同步 → 复习 UI → 提取子模块 → 提取工作台 → 初始化。题目 DOM 在交互模块初始化前创建。

## 题库模型

自定义题库 schema：

```json
{
  "version": 1,
  "categories": [{"id": "languages", "name": "语言学习"}],
  "subjects": [{
    "id": "english-grammar",
    "name": "英语语法",
    "categoryId": "languages",
    "questions": [{
      "id": "present-perfect",
      "question": "现在完成时的结构是什么？",
      "gist": "have/has + 过去分词。",
      "answer": "主语 + have/has + 过去分词，表示与现在有关的过去事件。"
    }]
  }]
}
```

类型和专题 ID 必须为以小写字母开头的 ASCII 字母、数字、连字符，最多 64 字符。题目 ID 使用字母、数字或连字符。`gist` 可选，题干和答案必填。导入同 ID 专题会替换专题内容，其他专题保留；稳定 ID 对应稳定进度。为另一道题复用旧 ID 会错误继承历史，请避免。

内置题库暂时保留富文本 HTML 以避免损失表格、代码块和流程图，并按专题存入 JSON。可信内置内容与用户导入的纯文本题库分开渲染。维护内置专题应修改 `data/subjects/<id>.json`，再运行 build；未来可以逐步改为 Markdown 内容，而不影响复习算法。

运行时自定义题库存储于 `knowledge-library-v1`。复习进度导出仅导出进度，不包含自定义题库，换设备时需同时导入对应题库 JSON 和进度 JSON。资料提取数据库的四个 store 保持不变，新增 categoryId 字段不需要升级 schema。

模块偏好存储于 `knowledge-library-preferences-v1`，包含 `recent`（去重后最多五个）、`names`（模块 ID 对应显示名称）和 `categories`（用户新建的模块）。首次升级根据现有卡片历史推导最近使用顺序；无使用记录时不预填模块。“全部知识”始终可用，完整模块清单位于管理弹窗。新建与重命名不修改内置题库 JSON 或卡片 ID。题库导入可选择覆盖目标模块，资料提取使用自身的类型选择控件。

## 复习规则与兼容性

- 等级阈值保持 30 / 60 / 85；准确率低于 40 时，等级最高为模糊。
- 连续两次熟练或掌握才毕业，中间出现模糊 / 忘记会清零 gate。
- 模糊间隔为 1 → 3 → 7 天；忘记后立即到期并强制回顾。
- 事件合并先去重，再按真实时间排序重放，导入时间不参与排期。
- 手动“未记忆”作为重置事件参与同步，不能被旧判分覆盖。
- 每题保留 60 条历史。新记录截断时保存前置 checkpoint；旧版本已经截断的历史无法恢复，复杂跨设备分叉与旧数据的长期累计值仍需进一步迁移设计。
- 人工标记同样推进等级和 gate，沿用原产品行为。

旧 localStorage 名称保持不变；本次不主动清空用户进度或 IndexedDB。旧专题独立 HTML 仅作为兼容跳转入口，源码备份在 archive，后续统一维护主工作台和 data。

## AI 与数据边界

Key 读取顺序为 `DEEPSEEK_API_KEY` → `deepseek.key`。`AI_MODEL` 可覆盖默认模型，`DEEPSEEK_BASE_URL` 指定兼容 chat/completions 地址。提示词不再绑定嵌入式角色，以用户给出的标准答案和资料为评分与出题依据。

本地服务默认只监听回环地址，拒绝跨来源浏览器 AI 请求，不提供登录系统或多人权限。适合个人本机使用，若要公网或团队部署，需要单独设计鉴权、额度管理与服务端持久化。

现有提取生成仍有每次知识点前 30 块 / 出题前 20 块的限制，没有把 50MB 文档全部发送给 AI；大型资料需要后续加入分批生成、去重与取消控制。OCR 限制每文件 30 页。第三方解析库和 AI 的完整真实网络链路没有纳入本次回归。

## 交付形式选择

HTML 是界面实现方式，Electron / Tauri 是应用外壳，两者可以组合，不必重写题库与算法。

| 方式 | 对当前项目的价值 | 成本 |
|---|---|---|
| 浏览器 + 本地 Node | 已可运行，维护简单，可按需局域网访问 | 用户仍需启动服务，存储依赖浏览器来源 |
| Electron | 内置 Chromium 与 Node，能复用当前 JS 后端，适合先做 Windows 桌面版 | 需新增主进程、打包、独立数据目录与更新策略，安装包通常较大 |
| Tauri | 使用系统 WebView，适合关注体积的桌面应用 | 需 Rust 工具链和平台适配；现有 Node 后端需 sidecar 或改写 |

建议当前先使用模块化 Web 版本；确认独立桌面窗口与安装包需求后优先 Electron。之后的数据应迁移到固定应用数据目录，避免随机服务端口产生多份浏览器进度。

参考：[Electron 官方介绍](https://www.electronjs.org/docs/latest/)、[Tauri 进程模型](https://v2.tauri.app/concept/process-model/)、[Tauri WebView 版本](https://v2.tauri.app/reference/webview-versions/)。
