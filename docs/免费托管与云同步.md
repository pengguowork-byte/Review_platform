# 免费托管 + Supabase 云同步

适用版本：3.0.0；本地流程更新：2026-10-02。服务平台配额与界面以官方当前说明为准。


## 本次范围

同步自定义题库、复习进度和模块配置（自定义名称、空模块、最近五个模块及使用时间、复习策略）。内置 296 道题随网页分发。原始 PDF、Word、图片，以及资料提取工作台的文本、未导入的生成结果，仍在设备本地，不上传云端。已确认生成题目导入题库后才参与同步。

前端仍可直接本地使用。云端静态版本提供复习和同步，不包含现有 Node AI 服务；AI 自测、生成题库需使用本地服务，或以后另行部署受认证保护的 AI 接口。AI 密钥绝不能放入前端或 Pages 环境构建变量。

## 1. 创建 Supabase 免费项目

1. 在 https://supabase.com/dashboard 创建 Free 项目。选择合适区域，数据库密码自行保管。
2. 在 SQL Editor 粘贴并执行本工程 `supabase/schema.sql`。它建立 `review_sync` 表、RLS 用户隔离策略和原子版本更新函数。不要关闭 RLS。
3. 在 Authentication → Users → Add user 创建自己的邮箱密码账号。第一版没有公开注册入口，也不使用短信或验证邮件，可在控制台创建并确认用户。
4. 取得 Project URL 和 Publishable key（以 `sb_publishable_` 开头），或旧版 `anon` key。不要使用 `sb_secret_` 或 `service_role`。
5. 无需创建 Storage bucket。本项目没有原始资料上传接口。

免费项目会在一周不活跃后暂停，需在控制台恢复；免费版不含自动数据库备份。保留完整备份作为本机备份，观察数据库、出站流量和 Auth 用量，不必先升级付费计划。实际额度以官方 https://supabase.com/pricing 为准。

## 2. 构建可上传的静态目录

在工程目录 PowerShell 中运行（系统 Node 18+，或替换为 `./runtime/node.exe`）：

```powershell
$env:SUPABASE_URL = 'https://你的项目标识.supabase.co'
$env:SUPABASE_PUBLISHABLE_KEY = 'sb_publishable_你的公开密钥'
node scripts/build-cloud.cjs
node --test tests/*.test.cjs
```

产物在 `dist/`。构建只复制公共网页资源，不复制 `deepseek.key`、服务器代码、SQL、原始归档、runtime、测试或本机资料。构建拒绝 secret/service_role 密钥。URL 和 Publishable key 是客户端公开配置，可以出现在网页里；用户数据由登录认证和 RLS 保护。

未提供环境变量时，构建仍成功，但网页显示「本地模式 · 云同步待配置」。不能因此宣称已经上线同步。

## 3. 免费托管：Cloudflare Pages

### 手动上传，适合首次部署

1. 登录 Cloudflare 控制台，进入 Workers & Pages，创建 Pages 项目，选择直接上传静态资产（界面名称可能变化）。
2. 上传 `dist/` 内的内容，确保 `index.html` 位于上传根目录。不要上传整个 Git 工程目录。
3. 使用平台提供的 `https://项目名.pages.dev` 地址，不必购买域名。
4. 更新时重新构建并上传整个 `dist/`，保持资源、Service Worker 和云配置版本一致。

### GitHub 自动构建，适合后续维护

直接上传创建的 Pages 项目不能原地切换为 Git 集成；若需要自动部署，应一开始选择 Git 集成，或另外创建 Git 集成项目并迁移网址。

代码推送到 GitHub 后，在 Pages 中连接 `pengguowork-byte/Review_platform`，生产分支选择 `main`：

- Framework preset：None。
- Build command：`node scripts/build-cloud.cjs`。
- Build output directory：`dist`。
- Root directory：仓库根目录（本仓库根就是内层工程目录）。
- 构建环境变量：`SUPABASE_URL`、`SUPABASE_PUBLISHABLE_KEY`，按实际配置。

这两个变量不是数据库密码。不要添加 AI 密钥或 Supabase 管理密钥。首次部署后更新 Supabase Authentication 的 Site URL 为生产 HTTPS 地址，便于后续扩展登录流程。本版邮箱密码登录无需 OAuth 重定向。

Cloudflare 官方部署说明：https://developers.cloudflare.com/pages/get-started/direct-upload/ 与 https://developers.cloudflare.com/pages/get-started/git-integration/ 。

## 4. 双端使用与已有数据迁移

1. 电脑和手机打开同一个部署网址，点击「账号与同步」，登录同一邮箱账号。
2. 新账号初始仅有内置题库。点「迁移本机数据到此账号」，显式复制该网址下原来的访客题库、模块和进度。访客数据仍保留。
3. 本机 `localhost` 数据与新 `pages.dev` 地址不同源，不会自动出现。先在本地工程“备份与恢复”导出完整备份，在云端网页登录目标账号后恢复，核对题库、进度、模块名及策略，再同步。也可分别导入题库和进度，但进度文件不包含模块配置。
4. 点「立即同步」。手机登录后会拉取数据；有新的题库或配置时，安全状态下自动应用内容，无需整页刷新；编辑或自测期间暂缓，关闭后通过内容更新入口应用。多标签页或账号范围失效的旧页面仍需刷新。
5. 手机可以使用浏览器的「安装应用 / 添加到主屏幕」。在支持安装提示的浏览器也会显示应用内「安装应用」按钮。
6. 离线复习先本地保存；联网、回到前台、登录后、手动同步时补同步。前台还会每 60 秒检查一次，修改后约 1.5 秒提交；后台关闭应用不保证同步。
7. 退出后回到访客数据；账号本地缓存保留在本机，重新登录可继续使用。共享设备上不要把退出视为清除本机所有数据。

## 合并、失败与限制

- 本地存储沿用现有 localStorage，增加账号命名空间，不破坏旧数据；资料提取仍使用自己的 IndexedDB。待上传状态由本地快照与上次成功同步基线比较得到，不依赖后台运行。
- 初版每账号保存一个 JSON 快照，最大 8 MB；实际 localStorage 容量因浏览器而异，可能更小。同步有改动时上传合并后的快照，不是逐题增量上传；适合个人题库，后续大量用户/数据可拆为逐题表和事件表。
- 题库按专题 ID、题目 ID 和字段做三方合并；模块名称按 ID 合并。同一字段两端同时变更会提示逐项选择；删除与编辑冲突也不会静默覆盖。
- 复习历史按事件合并。登录账号的新复习事件有唯一 ID，保留完整历史，避免每 60 条截断导致离线长时间后丢掉并发事件。旧数据已经被旧版本丢弃的历史无法恢复；旧事件仍按旧规则去重。排序依赖设备时间，应保持设备自动校时。
- 云端通过版本比较原子写入；被其他设备抢先更新会重新读取合并。无法稳定写入时保留本地数据并提示重试。
- 同一浏览器多标签页发生数据变化时，旧页面提示刷新并停止同步，避免用过时 UI 覆盖新数据。
- 登录用户只访问自己的行；不同账号的缓存及同步基线隔离。原始文件不在快照中，不建立云端文件存储。
- App 更新缓存采用整体版本，用户点击“更新应用版本”后启用新版本。API、Supabase 响应及用户上传文件不进入 Service Worker 缓存。
- Service Worker 需要 HTTPS（localhost 开发例外）；`file://` 仅保留原有本地功能，不支持 PWA 安装与 Service Worker。

## 上线验收

代码测试并不代替真实 Supabase/手机验收。创建项目后需要：

1. 在两台设备登录同账号；电脑导入题库、改模块名、标记熟练，手机同步后确认相同结果。
2. 离线手机标记题目，再联网打开平台；确认电脑获得记录且重复同步不会重复计数。
3. 同时修改同一题目字段或模块名，验证冲突提示；两端修改不同字段验证合并。
4. 使用第二个账号确认无法读写第一个账号的行；未登录无法读取表或调用保存函数。
5. 验证页面重开仍保留数据，退出回到访客数据；本地迁移不会自动跨账号复制。
6. 在实际 Android/iOS 浏览器安装并关闭网络测试缓存题库；资料提取外部解析库和 AI 功能不承诺离线使用。
7. 发布一次新版本，确认主动刷新能切换新版。

官方权限模型：https://supabase.com/docs/guides/database/postgres/row-level-security 。
